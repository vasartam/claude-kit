# Грабли оболочек Windows: инструмент Bash, Git Bash, PowerShell, WSL

Общие грабли (кавычки через stdin, контейнеры, деплой, секреты) — `knowledge/shell-pitfalls.md`.

- **Инструмент Bash агента на Windows и обратные слэши.** Двойной `\\` доходит до команды
  одиночным `\` — даже внутри `<<'EOF'` (проверено `od -c`, 2026-09-25); одиночные `\n`, `\v`,
  `\b` доходят как есть и в Python-строке без `r` становятся управляющими символами: путь
  `D:\dev\video…` превращался в «D:\dev<VT>ideo…», `\backup` — в «<BS>ackup», JSON `"D:\\dev"`
  терял экранирование. Файлы со слэшами писать инструментами Write/Edit или собирать слэш через
  `chr(92)`; после правки искать управляющие символы (`ord(c) < 32`, кроме перевода строки и
  табуляции). На macOS `\\` доходит без изменений (проверено 2026-10-03).
- Непарная одинарная кавычка внутри heredoc (например, «Python'ом»), похоже, ломает команду
  целиком («unexpected EOF while looking for matching») — обходить формулировкой без апострофа.
  На macOS не воспроизводится (2026-10-03).
- **Вложенные кавычки через `wsl.exe`** (`wsl.exe -e bash -lc 'ssh host "… \"…\" …"'`) — скрипт
  в файл и через stdin: `wsl.exe -e bash -lc "ssh host 'sh -s' < /mnt/c/…/script.sh"`.
- Из PowerShell не передавать в `bash -lc` строки со скобками и `|` в регулярках — ломается
  кавычивание.
- В Git Bash аргументы-пути для `wsl.exe` портятся — `MSYS_NO_PATHCONV=1 wsl.exe …`.
- Windows-Python не открывает пути Git Bash вида `/c/Users/...` — давать `C:/...` или относительные.
- PowerShell 5.1: нет `&&`, `||`, `?:`; `2>&1` у внешних программ превращает stderr в ошибки.
  Скрипты `.ps1` с кириллицей — в UTF-8 с BOM, иначе 5.1 читает их в кодировке ANSI: байты
  «—» и «…» становятся «фигурными кавычками» cp1251, парсер видит незакрытую строку и сыплет
  «Missing closing '}'» далеко от места (2026-09-26). Инструмент Write пишет без BOM — после
  него пересохранять: `[IO.File]::WriteAllText($p, [IO.File]::ReadAllText($p, [Text.Encoding]::UTF8), (New-Object Text.UTF8Encoding $true))`.
  В строках `"$f: текст"` двоеточие после переменной читается как диск (`$f:`) — писать `"${f}: …"`.
  Задачу планировщика (`schtasks /create`) без прав администратора создать нельзя (Access is denied)
  даже для себя — автозапуск через папку `shell:startup` (`.vbs` с `WScript.Shell.Run …, 0`).
- **Файлы между ФС** (WSL ↔ примонтированный диск) внутри рабочей копии не копировать: файл
  однажды так обнулился. Править на месте одной стороной.
- **`curl` в Windows (schannel) падает `CRYPT_E_REVOCATION_OFFLINE` (код 35)** на исправных
  сайтах с сертификатами Let's Encrypt — не может проверить отзыв через сеть машины. Это не
  поломка сайта: проверять из WSL (`curl` там на OpenSSL) или `curl --ssl-no-revoke`.
