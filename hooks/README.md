# hooks — хуки Claude Code общего слоя

Скрипты на Python 3.9+ без зависимостей; работают в любой оболочке — в терминале (в herdr и без) и в
приложении. Какие события на какой скрипт — `hooks/hooks.json` (штатный формат плагина Claude Code,
`${CLAUDE_PLUGIN_ROOT}` — каталог слоя). В `~/.claude/settings.json` их вписывает `scripts/link.py`
вместе с хуками выбранных слоёв (`terminal/hooks/` и т. д.): exec-форма, абсолютные пути, тот python,
что запустил link.py. Правка скрипта действует сразу; правка `hooks.json` — после повторного
`python scripts/link.py`, новые записи `settings.json` идущие сессии подхватывают без перезапуска
(замечено 2026-09-26).

| Скрипт | События | Что делает | Имя для `exclude` |
|---|---|---|---|
| `context-guard.py` | `SessionStart`, `UserPromptSubmit`, `PostToolUse`, `PreCompact` | знания — на полочки до сжатия контекста (ниже) | `context-guard` |
| `model-advisor.py` | `UserPromptSubmit` | строка «model-advisor: …» к каждому промпту — сверить модель и effort с задачей | `model-advisor` |
| `limit-guard.py` | `PreToolUse`, `UserPromptSubmit` | пауза у лимита подписки и продолжение после сброса | `limit-guard` |
| `msk_time.py` | `UserPromptSubmit`, `PostToolUse`, `Stop` | время в контексте (пояс — ключ `clock`); метку `_03.10.2026 16:40 МСК_` в конец ответа дописывает мод `msk-time`, без него — модель | `msk_time` |
| `session_state.py` | — | модуль, не хук: состояние сессии для трёх хуков выше (ниже) | — |
| `knowledge_guard.py` | — | заглушка на один выпуск (ниже) | — |

Машине хук не нужен — его имя в `exclude` конфига машины `~/.claude/claude-kit.json`. Хуки одного
события Claude Code запускает параллельно: порядок их текстов в контексте не гарантирован, общие файлы
пишутся атомарно (`write_json`).

Модель, лимиты и порог автосжатия Claude Code в хуки не передаёт — их собирает `session_state.py`
(ниже) из мода `mods/session-state`, статусной строки и транскрипта.

Заглушки по старым путям — `knowledge_guard.py` здесь и `terminal/hooks/context-guard.py`,
`model-advisor.py`, `limit-guard.py`: передают вход и аргументы новому хуку (на Windows —
`subprocess.call`, иначе `os.execv`), нового нет — молча выход 0. В `hooks.json` их нет. Держат живые
сессии со старым снимком хуков и окно между `git pull` и `link.py`. Удалить следующим выпуском, после
перезапуска всех сессий на обеих машинах (`CHANGELOG.md`).

Проверка без Claude Code: `for t in hooks/test_*.py; do python3 "$t"; done` (на Windows —
`python hooks\test_<имя>.py` по каждому файлу); мод — `mods/session-state/README.md`.

## context-guard

Задача (владелец, 2026-09-26): перед `/compact` и перед автосжатием всё ценное из разговора
раскладывается по полочкам (навык `session-extract-knowledge`; конец сессии — `session-end`, он
вызывает его сам), — чтобы сжатие посреди работы ничего не стёрло. С 2026-10-03 — одна схема на обеих
машинах: прежние `knowledge_guard` общего слоя и `context-guard` слоя terminal слиты (решение
владельца). От оболочки зависит только концовка — есть ли панель herdr (`$HERDR_PANE_ID`).

| Событие | Что делает |
|---|---|
| `UserPromptSubmit` | ниже `BASE_eff` — тишина, отложенный порог сбрасывается; с `BASE_eff` (или отложенного порога) — вопрос: по умолчанию сжать (раскладка и концовка, ниже), а если запросу правда нужен весь контекст — выполнить его и отложить проверку; с `HARD_eff` откладывать нельзя. Промпт-вызов навыка раскладки пропускает |
| `PostToolUse` | `echo knowledge-sorted` (Bash) — отметка «разложено»; переходное `echo knowledge-keep-context 700k <зачем>` — отсрочка до 700k (не дальше `HARD_eff`); пока сжатие отложено (без панели) — напоминание разложить знания, на 1-м и каждом 4-м вызове |
| `PreCompact` | раскладка свежая — сжатие идёт; иначе отказ и раскладка (концовка) |
| `PreCompact` + `rewake` (`asyncRewake`) | без панели, после отложенного ручного `/compact`: будит модель, даже если сессия простаивает |
| `SessionStart` | новый цикл после `startup`/`clear`/`compact`; сжатие прошло без раскладки — путь к полной записи сессии (JSONL цел и после сжатия); чистка состояний старше 30 дней |

Отсрочка — строка-цитата в самом конце ответа (после метки, если её пишет модель): «> контекст 420k, проверка
отложена до 470k: <причина>». Хук берёт порог из ответа на прошлый промпт: округление до 10k вверх, не
дальше +150k (`CONTEXT_GUARD_STEP`) от текущего; пример внутри текста не считается. Порог следующей
проверки — `~/.claude/session-status/<id>.ctx-mark`, статусная строка показывает его как `⚑470k`.
Вручную — `python3 hooks/context-guard.py defer <session_id> 650k`.

| Концовка | Панель herdr | Без панели (приложение, терминал вне herdr) |
|---|---|---|
| вопрос «сжать» | к запросу не приступать: раскладка, затем `~/.claude/bin/claude-compact --resend <файл>` — после сжатия тот же запрос придёт снова (файл — `~/.claude/context-guard/<id>.prompt.md`) | с модом `context-compact` (признак `~/.claude/context-guard/<id>.compact-mod`, `ok: true`) — как в панели, только сигнал моду: `echo "context-compact --resend <файл> -- <инструкция>"` (в двойных кавычках) (`mods/context-compact/README.md`); без мода — раскладка, запрос, последней строкой просьба владельцу `/compact <инструкция ≤ 250 символов>`; знания уже разложены — только сигнал моду или напоминание |
| ручное `/compact` без раскладки | отказ (JSON `decision: block`), агенту после конца хода — `/session-extract-knowledge` через `herdr agent wait/prompt` (не чаще раза в 30 мин); раскладка сама вызовет `claude-compact` с инструкцией исходного `/compact` | отказ кодом 2 один раз, `rewake` будит модель — разложить и повторить `/compact` сигналом моду (без мода — попросить владельца); повторное проходит всегда |
| автосжатие без раскладки | отказ, пока раскладка нужна, идёт или кончилась (сожмёт `claude-compact`); проходит после одной отметки без навыка, у 92 % окна (`CONTEXT_GUARD_AUTO_CEILING`) и после 40 отказов | отказ кодом 2 и напоминания до отметки `echo knowledge-sorted` (вызова навыка мало: раскладка может ещё идти); проходит, когда до края окна < 40k, и после 40 отказов |

Пороги (токены контекста — вход и кэш, без вывода):

- `HARD_eff = min(HARD, порог автосжатия)`, `HARD` — 900k (`CONTEXT_GUARD_HARD`); автосжатие
  выключено — 92 % окна.
- `BASE_eff = min(BASE, max(HARD_eff − STEP, 60 % HARD_eff))`, `BASE` — 300k (`CONTEXT_GUARD_BASE`).
  Окно 1M с `autoCompactWindow` 500k — 467k/300k, 200k-модель — 167k/100k.
- Порог автосжатия — от `session_state` (ниже). `autoCompactWindow` в `~/.claude/settings.json`
  (владелец ставил 500000 2026-09-27; link.py его не трогает) опускает и его, и `HARD_eff`: сжатию не
  нужно ждать края окна, длинная сессия дешевле. Вернуть — `/autocompact auto`.

Раскладка свежая — после отметки `echo knowledge-sorted` набралось не больше 20k токенов
(`CONTEXT_GUARD_MIN_UNSORTED`) или после вызова навыка `session-extract-knowledge`/`session-end` (с
префиксом плагина или без) промптов пользователя не было. Исключение — автосжатие без панели: ему нужна
отметка. Сессия, начатая до подключения хука, считается целиком неразложенной.

- Не трогает субагентов (`agent_id`: у них своё сжатие) и сессии без человека
  (`CLAUDE_CODE_ENTRYPOINT=sdk-*`: `claude -p`, Agent SDK). Нет замера (ни мода, ни транскрипта) —
  молчит и сжатию не мешает.
- Выключить — `CONTEXT_GUARD_OFF=1` (прежнее `KNOWLEDGE_GUARD_OFF=1` тоже) или `exclude: ["context-guard"]`.
- Переменные: `CONTEXT_GUARD_BASE`, `_HARD`, `_STEP`, `_AUTO_CEILING`, `_MIN_UNSORTED`, `_KEEP_MAX`
  (предел для `knowledge-keep-context`), `_REWAKE_DELAY`; у трёх последних запасные `KNOWLEDGE_GUARD_*`.
  Токены — числом или «300k», мусор — значение по умолчанию. `CONTEXT_GUARD_DUMP=<файл>` пишет вход хука.
- Состояние — `~/.claude/context-guard/<session_id>.json`; его и `.prompt.md` удаляет чистка через 30
  дней. Своего нет — подхватывается `~/.claude/knowledge-guard/<session_id>.json` прежнего knowledge_guard:
  переход без волны напоминаний, его отсрочка становится порогом проверки.
- Тесты — `hooks/test_context_guard.py`, концовка с панелью — с фальшивым `herdr` (не на Windows).

Почему так:

- Вопрос — на старте промпта: модель уже видит следующую задачу и решает, нужен ли для неё весь
  контекст. Лестница напоминаний 50/75/90 % и напоминания на `Stop` ушли со слиянием.
- Отсрочка — цитатой в ответе, а не командой `defer`: в режиме auto классификатор блокирует её как
  самомодификацию (29.09.2026). Не дальше +150k: модели охотно откладывают «по инерции». Отсрочка дальше
  порога автосжатия бессмысленна — там всё равно сработает `PreCompact`, отсюда `HARD_eff`; `BASE_eff` —
  чтобы при низком пороге (200k-модели, `autoCompactWindow` < 333k) вопрос вообще задавался.
- Раскладывает **та же модель** (она знает, что ценно), а не отдельный `claude -p` по записи: тот
  дорог, правит те же файлы параллельно с сессией и хуже понимает контекст. Оценка 2026-09-26: вынос в
  сессии — ~10–15 запросов по уже закэшированному контексту C (чтение кэша — 0,1 от входа), итого
  ~1–1,5·C входных токенов; внешний агент без кэша — ~0,3–0,5 млн за прогон и без выводов
  инструментов. Главный рычаг экономии — размер контекста, а не частота выноса: запрос на 800K в 8 раз
  дороже запроса на 100K.
- `PreCompact` принимает только хуки-команды (не `prompt`/`agent`) и сам ничего не может сказать
  модели: при ручном `/compact` его stderr видит только владелец. Поэтому без панели модель будит
  второй обработчик с `asyncRewake`, а при автосжатии просьба доходит через `PostToolUse`; в панели
  herdr — промпт агенту через `herdr agent prompt`.
- В панели автосжатие отменяется и после вызова навыка: раскладка сама зовёт `claude-compact`, иначе
  сжатий будет два (29.09.2026). Отказов — не больше 40: с `autoCompactWindow` 500k при окне 1M они
  иначе шли бы до 920k.
- Отметка — команда `echo knowledge-sorted`: хук видит её в `PostToolUse` со своим `session_id`,
  модели не нужно знать ни id, ни путь к состоянию.

## session_state

Модуль на три хука: `session_state(inp, fields=…)` считает только нужные группы (`model`, `effort`,
`ultracode`, `context`, `limits`, `day`) — хуки висят на каждом вызове инструмента с таймаутом 10 с.
limit-guard берёт только лимиты, context-guard — модель и контекст, model-advisor — всё. Функции не
бросают исключений: чего нет — `None`; источник каждого поля — в `src`.

| Источник | Файлы | Где есть |
|---|---|---|
| мод `session-state` (`mods/session-state/README.md`) | `~/.claude/session-status/<id>.state.json` | обе оболочки, сессия запущена с модом |
| статусная строка `terminal/bin/claude-statusline` | `<id>.json`, `rate-limits.json`, `week-budget.json` там же | терминал |
| транскрипт | `transcript_path` из входа хука, с конца, до 64 МБ | везде |

- Каждое поле — из самого свежего показания (мод — `at` блока, транскрипт — `timestamp` записи,
  статусная строка — mtime файла); ближе 2 с — мод > статусная строка > транскрипт. Статусная строка
  перезаписывает файл каждую секунду, поэтому по mtime она в счёт только для модели, effort и окна;
  токены от неё (`statusline~`, точность 1 % окна) — только когда нет ни мода, ни транскрипта.
- Токены — вход + `cache_creation` + `cache_read`, без вывода: так считают мод, статусная строка и
  `get_usage`. Сразу после сжатия — `postTokens` границы (`after_compact`).
- Отметка сжатия `<id>.compact.json` (`note_compact`; пишет context-guard на `SessionStart` после
  сжатия, `at` — когда PreCompact его пропустил): показания токенов старше неё не берутся, до нового
  показания `tokens` нет. Первый промпт после сжатия приходит через доли секунды, а транскрипт
  дописывается с задержкой — без отметки хуки видели последний ответ до сжатия (319k при 28k, 03.10.2026).
- Порог автосжатия — от мода (`session.usage({breakdown: 'summary'})`), без него —
  `min(CLAUDE_CODE_AUTO_COMPACT_WINDOW или autoCompactWindow, окно) − 33k`; настройки — локальные
  проекта > проекта > `~/.claude/settings.json`. Сходится с замерами при окне 1M (967k, с 500k — 467k);
  для окон < 1M (200k → 167k) — гипотеза, не замерено. Мод сказал «автосжатие выключено» — порога нет.
- Лимиты — все `*.state.json` за 8 суток и `rate-limits.json`. Показание годно, пока его сброс впереди:
  внутри окна процент только растёт, старое показание — нижняя граница. По окну побеждает поздний сброс
  (до минуты), потом больший процент; возраст показания — `age`.
- Дневная норма недельного — формула «сегодня S/N%» статусной строки: остаток на начало дня ÷
  оставшиеся рабочие дни до сброса. Начало нового дня модуль сам пишет в `week-budget.json` (в
  приложении статусной строки нет), но только по показанию, снятому уже в этих сутках.
- Ultracode — из транскрипта, кеш `<id>.ultra.json`: дочитывается только прирост файла.
- Общий ввод-вывод хуков: `read_input`, `emit_context`/`emit_json` (ASCII: на Windows кириллица в
  stdout иначе бьётся), `block_stderr`, `write_json` (tmp и `os.replace`, ошибка — тихий пропуск).
  `cleanup_status` удаляет старше 30 дней `*.state.json`, `*.ultra.json`, `*.ctx-mark`, `*.compact.json`, `*.advice.json` и брошенные `*.tmp.*`.
- `~/.claude` — это `CLAUDE_CONFIG_DIR`, если задан (так изолируются тесты); статусная строка его не знает.
- Отладка: `python3 hooks/session_state.py <session_id> [transcript.jsonl]` — результат JSON с `src`.

## model-advisor

Строка к каждому промпту — данные; совет по лимитам и ожидание решает код. Например:
`model-advisor: Opus 5.5, effort high, контекст 312k — 66% до автосжатия (467k), ultracode выкл; 5ч 42%
(сброс 18:00), 7д 15% (сброс 06.10 10:00, сегодня 6/17% нормы). Правила — …`

- Данные — `session_state`, всё сразу; нет ни модели, ни лимитов — молчит. Неизвестное — `?`; лимитам
  больше 15 мин — «данные N мин назад»; мод сказал «автосжатие выключено» — «автосжатие выкл».
- `limits tight` — 5ч ≥ 70 % (`TIGHT_5H`) или за день потрачена дневная норма недельного.
- Совет — формальная таблица `decide`/`cheaper`, задачу хук не оценивает:

  | условие | совет |
  |---|---|
  | лимиты не tight | нет |
  | tight, ultracode вкл | ultracode выкл (и шаг ниже, если есть) |
  | tight, Fable | Fable → Opus |
  | tight, effort xhigh/max (не Fable) | effort → high |
  | tight, Opus с effort до high | Opus → Sonnet |
  | tight, Sonnet/Haiku с effort до high, модель неизвестна | нет |

  Раз на ситуацию: ключ — окно повода (`5h:<сброс>`, `day:<начало дня нормы>`), выданные ключи — в
  `session-status/<sid>.advice.json`. Совет дан — до нового окна молчит, принят он или проигнорирован;
  не записался файл — совета нет. В строке: `Совет (лимиты на исходе): … — предложить до работы.`
- Только с советом и только в панели herdr: `wait: ~/.claude/bin/claude-autocontinue <sid> 120` — совет
  без ответа 2 мин (`MODEL_ADVISOR_WAIT`), и агенту уходит «продолжай»; следующий промпт после совета хук
  пропускает (файл `<sid>.advised`). Совета нет — `wait:` нет. Под herdr всегда — метка вкладки и
  условие её смены: только при смене основной задачи.
- Пропускает субагентов, вызов навыка раскладки и служебные промпты `claude-compact`/`claude-autocontinue`.

Совет по задаче (что хук знать не может) — «Модель и effort» корневых правил и `knowledge/model-advice.md`,
без ожидания: они грузятся раз за сессию, а строка хука идёт с каждым промптом (~100 токенов вместо ~600).

## limit-guard

Лимиты 5 ч и 7 дн общие для аккаунта; хук берёт их у `session_state.read_limits` (транскрипт не
читает): показание годно, пока его сброс впереди. На 90 % (`LIMIT_GUARD_5H`, `LIMIT_GUARD_7D`) первое же
действие отклоняется с инструкцией: довести правку до целого состояния, `/session-extract-knowledge`,
записать план в `~/.claude/limit-guard/<sid>.resume.md` и поставить разовое `CronCreate` на 3 мин после
сброса. Через 10 мин (`LIMIT_GUARD_GRACE`) действия отклоняются до сброса; промпт человека снова даёт
10 мин. Сабагент паузу не начинает, но после GRACE получает тот же отказ.

Координатор жив — хук молчит: паузу и пробуждение тогда ведёт навык `limit-guard` или координатор
`night-work` (слой desktop), а хук отказал бы ему в инструментах и дал бы второе пробуждение. Признак —
mtime `~/.claude/limit-guard/alive-limit-guard` (свежее 30 мин) или `alive-night-work` (свежее 75 мин):
их пишут сами навыки на каждой своей проверке (раз в 20 мин и раз в час), содержимое не важно. Файлов
нет (терминал, координатор не запущен) — хук работает сам.

Хук держать включённым. Выключатель — файл `~/.claude/limit-guard/off`: действует только до ближайшего
сброса 5 ч, потом хук удаляет его сам. Ставить его — только совсем близко к лимиту (например, чтобы
включение не поставило на паузу все сессии сразу); не после тестов и не «на всякий случай». Мешает —
чинить хук (порог, текст), а не выключать. Тесты изолируются через `CLAUDE_CONFIG_DIR`. Случай
29.09.2026: хук оставили выключенным после проверки, долгая фоновая сессия упёрлась в лимит, не
поставила себе продолжение и после сброса не проснулась.

## msk-time

Задача (владелец, 2026-09-26): каждая сессия знает текущее время и заканчивает
итоговый ответ отметкой в одном формате — чтобы по истории было видно, когда что сказано, и
чтобы сессия сама понимала, что владелец не приходил день-два, без его подсказки.

Формат (решение владельца 2026-10-03, один на всех машинах) — последняя строка итогового
ответа курсивом, без дня недели и значков: `_03.10.2026 16:40 МСК_`. До этого дома была
`🕒 26.09.2026 18:06 МСК, сб` — такую Stop больше не принимает.

Часы — ключ `clock` в `~/.claude/claude-kit.json` (настройка машины, не в git; `link.py --init` его не
трогает), его же читает мод `msk-time`:

```json
{"clock": {"utc_offset": 3, "label": "МСК", "farewell": "Пока."}}
```

`utc_offset` — часы от UTC, постоянное смещение (по умолчанию — пояс системы на момент запуска хука);
`label` — подпись после времени (по умолчанию `UTC+N`; `""` — без подписи, только дата и время); `farewell` — слово, которым кончается сессия:
ответ из него метку не получает (по умолчанию нет — тогда `session-end` отвечает «Готово.»).

| Событие | Что делает |
|---|---|
| `UserPromptSubmit` | «Сейчас … <подпись>. Прошлый ответ в этой сессии — … (N назад)» + правило отметки; перерыв ≥ 2 ч — напоминание перепроверить внешнее состояние (CI, MR, задачи), а не докладывать по памяти |
| `PostToolUse` | «Сейчас … <подпись>», не чаще раза в минуту на сессию (у субагентов — нет) |
| `Stop` | в `last_assistant_message` нет отметки или она расходится с часами (отстаёт > 4 мин или опережает > 1 мин) — ход продолжается одной строкой с верным временем; повторно не блокирует (`stop_hook_active`). Ответ, последняя строка которого — слово прощания `clock.farewell` (так кончается `session-end`), отметки не требует |

- Отметка ищется в последних 400 символах: после неё можно дописать короткую строку-цитату
  (например, пометку контроля контекста).
- Москва — фиксированный UTC+3 (переходов нет с 2014 г.), tzdata не нужна.
- Сессии без человека (`CLAUDE_CODE_ENTRYPOINT=sdk-*`) не трогает: вывод `claude -p` читают
  скрипты, лишняя строка его испортит.
- Состояние — `~/.claude/msk-time/<session_id>.json` (прошлый запрос, прошлый ответ, минута
  последней заметки), старше 60 дней удаляется. Сессия без состояния берёт время последней
  записи из JSONL сессии («Прошлая активность»).
- Любая ошибка — тихий выход 0: хук не ломает сессию. Отладка: файл
  `~/.claude/msk-time/debug` включает журнал событий `debug.log`; `MSK_TIME_TRACE=1` —
  трассировку ошибок.

Почему так:

- Время даёт хук, а не модель: своих часов у модели нет, без заметок она выдумывает время
  (на работе до хука метка «из будущего» и UTC вместо МСК повторялись не раз).
- Заметка после инструментов — раз в минуту, а не на каждый вызов: при долгой работе отметка
  точна до минуты-двух, а в контекст уходит ~20 токенов в минуту работы.
- `Stop` сверяет, а не пишет сам: хук не может дописать текст в ответ, только вернуть ход
  модели. Проверено живьём 2026-09-26: соседняя сессия закончила ответ отметкой 18:06, Stop в
  18:07 её принял.
