# Связка ключей macOS: `security` и учётки Claude Code

## Команды

- Прочитать: `security find-generic-password -s "<сервис>" [-a <аккаунт>] -w` — печатает
  **секрет**: сразу в переменную или в тот же процесс, в вывод не пускать. Без `-w` — только
  атрибуты записи (аккаунт `acct` и т. п.).
- Записать: `security add-generic-password -U -s "<сервис>" -a <аккаунт> -w <значение>`
  (`-U` — обновить существующую).
- Первое обращение нового процесса к чужой записи показывает диалог; «Разрешать всегда» снимает его.

## Claude Code: OAuth MCP-серверов

Claude Code на macOS хранит учётки в записи `Claude Code-credentials` (JSON): `claudeAiOauth` —
вход в аккаунт, `mcpOAuth` — по ключу `<сервер>|<хеш>` на каждый MCP-сервер с OAuth (`clientId`
динамической регистрации и токены).

**Симптом:** `/mcp` → сервер → Authenticate открывает страницу входа с
`invalid_client: unknown client_id`. Пункта «Clear authentication» в `/mcp` нет — только
Authenticate и отключение.

**Причина** (подтверждена 2026-10-02): в `mcpOAuth` осталась запись с `clientId` прошлой
динамической регистрации, без токена. Сервер авторизации эту регистрацию забыл, а Claude Code
заново не регистрируется.

**Лечение** — удалить только запись этого сервера, **одним процессом** (скрипт на python):
прочитать JSON (`find-generic-password -s "Claude Code-credentials" -w`), аккаунт взять из
атрибутов той же записи; удалить ключ сервера из `mcpOAuth`; записать
`add-generic-password -U -s "Claude Code-credentials" -a <аккаунт> -w <json>`; перечитать и
сравнить, при расхождении записать исходное значение. Значения не печатать; `claudeAiOauth` и
другие серверы не трогать. Затем `/mcp` → сервер → Authenticate — Claude Code регистрируется
заново, вход проходит. Владелец подтвердил, что помогло, и просил запомнить.

На Windows и Linux хранилище учёток другое — этот приём там не проверялся.
