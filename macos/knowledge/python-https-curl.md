# HTTPS из Python на Mac — через системный curl

Python с python.org (и любая сборка со своей связкой сертификатов) не смотрит в связку ключей
macOS. Если в цепочке есть корень, которого нет в его связке, — корпоративный CA, CA прокси-отладчика
(Charles, mitmproxy), сеть с перехватом TLS, — `urllib`, `requests`, `httpx`, `aiohttp` падают:
`SSLCertVerificationError: certificate verify failed: unable to get local issuer certificate`.
При перехвате TLS падают и внешние хосты, а не только внутренние. Системный `curl` берёт
сертификаты из keychain и проходит.

- **Признак, что правило пора применять, — любой питоновский код, который сам ходит по HTTPS.**
  Писать через `subprocess` + `curl -sS --fail-with-body --max-time N` сразу, а не после первого
  падения. *Случай (2026-09-09):* массовый загрузчик на `urllib` дал 100 % отказов, и это было
  уже второе напарывание — 1350 бесполезных попыток.
- Проверку сертификата не отключать (`-k`, `verify=False`) — это не выход.
- Много файлов — пакетный режим: `curl --parallel --parallel-max 10 -K <config>`, в config строки
  `url = "…"` / `output = "…"`.
- Качать во временное имя и переименовывать только целый файл: оборванный или убитый `curl`
  оставляет обрывок под настоящим именем, и следующий прогон примет его за скачанное.
