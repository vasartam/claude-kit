# Кэш uv разрастается от uvx

`~/.cache/uv/archive-v0` (каталог кэша — `uv cache dir`) — распакованные колёса, чтобы установка
шла копированием, а не распаковкой. Если MCP-серверы запускаются через `uvx`, кэш пухнет до
десятков ГБ: каждая пересборка окружения сервера — новая копия. *Случай (2026-09-10):* 21 ГБ,
997 записей; у одного сервера — 18 копий окружения по ~200 МБ, по одной на каждую пересборку.

- **Чистка:** `uv cache prune --force` — только неиспользуемое; `uv cache clean` — всё. Тогда
  `prune --force` убрал 1,07 млн файлов (16,8 ГБ), осталось 1,7 ГБ.
- **`--force` нужен:** лок держат живые MCP-процессы, без флага команда ждёт 300 с и падает
  `Timeout when waiting for lock … is another uv process running?`. Серверы убивать не надо —
  prune трогает только неиспользуемое, работа запущенных не прерывается.
- **Хардлинков в кэше нет** (число ссылок на файл — `stat -f %l` на macOS, `stat -c %h` на Linux —
  равно 1): рабочие `.venv` — отдельные копии, чистка их не ломает, освобождённое место реальное.
  Цена — следующая установка пакетов пойдёт из сети.
