# Перезапуск Claude Code в панели herdr

Утилита — `~/.claude/bin/claude-restart` (навык `/restart-session`, команда `/restart-cmd`,
хоткей `Ctrl+Shift+R` — [hotkeys.md](hotkeys.md)).

## Панель — это шелл, агент в нём

Процесс панели herdr — login-shell, а не агент: `claude ← zsh ← herdr server`. Выход из claude
(`/exit`, Ctrl+D) панель **не закрывает** — остаётся приглашение шелла, вкладка и её место в ряду.
Закрывать и пересоздавать вкладку ради перезапуска агента не нужно.

- herdr сам восстанавливает сессии: в `herdr api snapshot` у панели `agent_session`
  (`{"agent":"claude","kind":"id","value":"<uuid>"}`), после перезапуска сервера панели поднимаются
  как `claude --resume <uuid>`. Флагов и переменных исходного запуска снапшот не хранит; команду herdr
  набирает в интерактивном шелле панели, поэтому функции-обёртки `claude` из `~/.zshrc` её
  перехватывают — но в том виде, какими они были при старте этого шелла.
- Нужна **новая** сессия — голый `claude`, без `--continue`/`--resume`. `/clear` перезапуском не
  является: процесс тот же.
- Программно: `herdr agent start <имя> --kind claude --pane <pane> -- --resume <id>` (панель должна
  быть на приглашении шелла). Id сессии — `herdr agent get <pane>` → `.result.agent.agent_session.value`.
- **Агенты без имени**: поднятые herdr при восстановлении сервера (`agent list` → `name: null`)
  адресуются по id панели; `claude-restart` даёт им имя `claude-<панель>`.
- Текст через `herdr agent prompt` — **одной строкой**: многострочный приходит как вставка, и
  инструкции из вставки агент без явной просьбы не выполняет (25.09.2026).
- **Окно при запуске съедает промпт** (30.09.2026): пока Claude Code показывает окно подтверждения
  (например, с `--dangerously-load-development-channels`), herdr считает агента `idle`, и Enter от
  `herdr agent prompt` подтверждает выбор, а текст пропадает. Окно надо подтвердить самому
  (`herdr pane send-keys <панель> enter`, клавиши `up`/`enter`) и дождаться, пока закроется.
- Всплывашки `herdr notification show` по умолчанию выключены (`[ui.toast] delivery = off`, ответ
  `reason: disabled`).

## Что переживает перезапуск процесса claude

Проверено e2e 25.09.2026 на 2.1.282:

| Что | Итог |
|---|---|
| задания CronCreate (и `/loop` с интервалом) | `--resume` восстанавливает сам (вопреки «session-only» в описании) |
| будильник `/loop` без интервала (ScheduleWakeup) | теряется — `claude-restart` дожидается срока и шлёт тот же промпт |
| фоновые Bash, Monitor, фоновые субагенты | гибнут (`<task-notification>` со `stopped`), новый процесс сам их не поднимает — `claude-restart` снимает список (`claude-live-tasks.py`) до SIGTERM и передаёт первым промптом |
| черновик в поле ввода | теряется — поэтому перезапуск ждёт конца хода |

## claude-restart: устройство и добавки машины

SIGTERM процессу claude, ожидание, пока herdr отпустит панель (`agent_name_taken`,
`agent_pane_busy` herdr не повторяет — повторяет утилита), затем `herdr agent start … -- <прежние
флаги> --resume <id>`. Флаги берутся из argv процесса (`herdr pane process-info`), кроме выбора
сессии. Пустая сессия на диск не пишется — тогда без `--resume`. Повторное нажатие хоткея во время
перезапуска — не второй перезапуск (замок на панель).

Свои флаги и шаги машины (каналы, подтверждение окна при запуске) — не в утилите, а в необязательном
`~/.claude/claude-restart.local.zsh` (путь меняет `CLAUDE_RESTART_LOCAL`): функция
`restart_args PANE` правит массив `args` до запуска, `restart_started PANE` выполняется сразу после
старта, до первых промптов. Без файла утилита работает как есть.

## Фоновая сессия

Если во вкладке крутится `claude attach <короткий id>`, процесс живёт у демона Claude Code
(`bg-pty-host`/`bg-spare`). Опознать: `claude agents --json` → `"kind": "background"` или argv в
`herdr pane process-info`. `claude-restart` и `Ctrl+Shift+R` её не перезапустят (argv — `attach`),
флаги к ней не добавить, `/reload-plugins` каналы не подключает. Перевести в обычную, не теряя
разговор: `claude stop <короткий id>`, затем во вкладке с шеллом `claude <флаги> --resume <полный
sessionId>` (поле `sessionId` в `claude agents --json`). Сессия может показаться под старым
названием, переписка та же.

Фоновые задачи при таком перезапуске **не переносить**: 30.09.2026 вышло две копии сессии
(интерактивная и `claude bg-spare`), у каждой свои мониторы, действия двоились. Лечение — `kill`
лишнего `bg-spare` и сирот (ppid 1). После перезапуска проверить `ps`: ровно один набор
наблюдателей, дочерний своей сессии; задачи сессия поднимает сама по своему файлу состояния.
