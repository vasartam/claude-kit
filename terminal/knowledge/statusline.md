# Статусная строка claude-statusline

`~/.claude/bin/claude-statusline` — статусная строка Claude Code CLI (в Desktop её нет):

```
Opus 5.5 ● high · 📁 ~ · ▰▰▰▱▱▱▱ 31% 312k/1M ⚑650k · 5ч 42% ↻ 18:00 · 7д 15% ↻ пн 10:00 · сегодня 6/17%
```

Один самостоятельный bash-файл, нужен `jq` 1.6+; работает на macOS и Linux. Попутно пишет данные
хукам набора (читают через `hooks/session_state.py`) — формат не менять без него.

## Подключение

`~/.claude/settings.json`, верхний уровень (link.py этого не делает — вписать руками):

```json
"statusLine": {"type": "command", "command": "~/.claude/bin/claude-statusline", "padding": 0, "refreshInterval": 1}
```

Строка появляется у новых и идущих сессий через пару секунд. Проверка без Claude Code:
`echo '{"model":{"display_name":"Opus 5.5"},"effort":{"level":"high"},"context_window":{"context_window_size":1000000,"used_percentage":12}}' | ~/.claude/bin/claude-statusline`
→ `Opus 5.5 ● high · ▰▱▱▱▱▱▱ 12% —/1M` с цветами. Нужен терминал с 24-битным цветом.

## Как выглядит (решения владельца 29.09–01.10.2026)

Ориентир — сам Claude Code: самодельные цвета и мигание отвлекают от ответа. При правке сначала
найти, как это рисует Claude Code (`strings` по бинарнику версии), и повторить.

- **Отдельной строкой** над строкой режима, без выравнивания вправо (в строку `auto mode on` Claude
  Code её и не пускает; положение не настраивается).
- Модель — жирным фирменным `claude` rgb(215,119,87); пояснение «(1M context)» отбрасывается: в
  `model.display_name` оно есть только у сессий с окном 1M, размер окна и так виден в блоке контекста.
- Effort — жирным, как выбранный пункт меню `/effort` (тёмная тема): low `warning`, medium `success`,
  high `permission`, xhigh `autoAccept`, значки ○ ◐ ● ◉ ◈; max — радуга темы **без анимации**
  («иначе будет забирать внимание»); ultracode — `effortUltra`, появляется сразу после переключения.
- `📁 ~` — папка, в которой открыта сессия (`workspace.project_dir`, не `current_dir`: тот меняется от
  `cd` в Bash); домашняя — `~`, длинный путь — первый уровень, `…` и последний (`~/my-project/…/bar`).
  Нужна, потому что сессии открывают в разных папках; 📂 отвергнут — «в перспективе» (06.10.2026).
- Контекст — полоска из 7 делений `▰▱` (занятые — цветом, свободные — серым, непустой — хотя бы одно
  деление), за ней процент, затем «сколько из скольких». Цвет полоски, процента и размера рядом **одинаковый**, по занятым токенам: до 200k —
  зелёный, от 200k до 850k плавно к красному (оранжевый — посередине), выше — красный; ступенек нет.
  Та же шкала `heat` у процентов лимитов (5ч, 7д) и у «сегодня X/Y%» (доля нормы дня), пороги
  переведены в проценты: до 20% зелёный, от 20% до 85% плавно к красному, выше — красный
  (06.10.2026). Раньше была подпись
  `ctx` — её расшифровывали не все, потом 🧠 — «выглядит странновато» (06.10.2026).
- **Оттенки — по теме herdr** (06.10.2026: зелёный/красный строки выбивались из gruvbox владельца).
  Токенов темы herdr наружу не отдаёт (`herdr config` — только настройки), поэтому строка читает
  `name` из `[theme]` в `${HERDR_CONFIG:-~/.config/herdr/config.toml}` и берёт зелёный, жёлтый,
  оранжевый и красный этой темы (таблица `pal` в скрипте: gruvbox, dracula, nord, tokyo-night,
  catppuccin, one-dark). Темы нет в таблице или herdr не установлен — прежние цвета (зелёный
  25,200,60 … красный 255,50,60). Зелёный gruvbox — 78,186,101 (как `medium` у effort), а не его «green» `#b8bb26` и не `#8ec07c`: оба на экране читались как жёлтые (06.10.2026). Новую тему — добавить строкой в `pal`. Касается полоски и процента
  контекста, процентов лимитов и «сегодня»; модель и effort — цвета самого Claude Code, не трогаем.
- После ↻ — пробел.
- «Сегодня X/Y%» — сколько недельного лимита потрачено за день из дневной нормы: остаток на начало дня ÷
  оставшиеся рабочие дни (пн–пт) до сброса, выходной — один день; день начинается во время сброса
  недельного лимита (09:00), работа после полуночи — тот же день. Цвет — по доле нормы, шкала `heat`.
- `⚑650k` — на каком размере контекста следующая проверка; обычной яркостью (тусклые ножницы `✂` были
  непонятны). Необязательна: берётся из `<id>.ctx-mark`, который пишет хук context-guard, — строкой
  можно пользоваться отдельно от хука.
- После сжатия вместо 0 — оценка с «~».
- Служебные пометки хуков в ответах — **после** строки с датой и временем, цитатой `> …`: markdown
  ответа цвета не умеет, цитата заметна меньше всего.

## Проверка без Claude Code — осторожно

Скрипт **пишет** в общие `~/.claude/session-status/rate-limits.json`, `week-budget.json` и журнал
`usage-log/limits.jsonl`, если во входном JSON есть `rate_limits`: выдуманные лимиты с поздним
`resets_at` побеждают настоящие («свежее окно — с более поздним сбросом») и обманывают limit-guard
(06.10.2026 так «сброс» уехал на 16:58, а 7д стал 30%). В пробных JSON `rate_limits` не подавать;
нужны лимиты — `HOME=$(mktemp -d)`.

## Откуда данные

Проверено на CLI 2.1.284–2.1.288 (29.09–03.10.2026).

- В статусную строку Claude Code передаёт `model`, `effort.level`, `context_window`, `rate_limits`
  (`five_hour`/`seven_day`: `used_percentage`, `resets_at`; при наличии `spend_limit`),
  `transcript_path`. Лимиты — после первого ответа API и только при входе по подписке.
- В хуки модель и лимиты не приходят (`knowledge/claude-code-hooks.md`), поэтому строка пишет в
  `~/.claude/session-status/`: `<id>.json` (модель, effort, ultracode, окно, % контекста),
  `rate-limits.json`, `week-budget.json` (процент на начало дня). `hooks/session_state.py` сверяет
  их с файлом мода session-state `<id>.state.json` и берёт свежее. Лимиты общие для аккаунта, а
  приходят с последнего ответа своей сессии — у простаивающей устаревшие или без `five_hour`.
  Поэтому в `rate-limits.json` — самые свежие из всех сессий (позже сброс, при том же — больший
  процент), запись — при изменении и на каждом новом ответе API своей сессии (смена `current_usage`, ключ — `usage_key` в `<id>.json`): `ts` — когда лимиты последний раз подтверждены, а не менялись (иначе model-advisor писал «данные 70 мин назад» о процентах, которые просто не росли, 04.10.2026); окно с прошедшим сбросом — 0%, а недельное ещё и сдвигается вперёд на целые недели (сброс — в тот же день недели и час): иначе до первого ответа нового окна дневная норма считалась по прошедшей дате и строка писала «сегодня 0/100%» вместо 0/20% (07.10.2026). Сдвиг только в выводе строки, в `rate-limits.json` не пишется. Журнал роста процентов —
  `~/.claude/usage-log/limits.jsonl` (для `claude-usage-report`). Кроме строки, лимиты видят только
  моды (`session.measure`); `cachedUsageUtilization`
  в `~/.claude.json` — кэш `/usage`, обновляется почти только этой командой и источником не годится.
- **Ultracode** не передаётся никуда: строка берёт последнее из ответа `/effort` в транскрипте и
  вложений `ultra_effort_enter`/`exit` (`<kit>/knowledge/claude-code-context.md`). `hooks/session_state.py`
  ищет его по транскрипту сам: `<id>.json` отстаёт на промпт с `ultra_effort_enter`.
- Сразу после `/compact` (и в продолженной сессии до первого ответа) контекст приходит пустым — строка
  оценивает его по транскрипту: `compactMetadata.postTokens` или расход последнего ответа.
- `refreshInterval` минимум 1 с; прогон ~90 мс и ~9 мс процессора, ~1% ядра на сессию. Без него
  строка не перерисовывается, пока нет событий.

## Открытый сабагент: мод agent-view-status

Какой агент открыт на экране, Claude Code в строку не передаёт — всегда основная сессия; это знают
только моды (`ui.render` → `props.view.agentId`, `turn.step` → модель и effort запроса). Мод
`<kit>/terminal/mods/agent-view-status` пишет открытого агента в
`~/.claude/session-status/<id>.view.json`, и строка показывает `↳ <подпись> · <его модель> <effort> · <полоска и его контекст>` (контекст — по последнему ответу в
`<транскрипт без .jsonl>/subagents/agent-<id>.jsonl`; окно Haiku 200k, остальных — как у сессии).
Лимиты общие; `<id>.json` для хуков остаётся про основную сессию. Без мода строка работает как раньше.

Подключает `scripts/link.py` (`env.CLAUDE_CODE_PLUGIN_DIRS` в `~/.claude/settings.json`); не нужен —
имя `agent-view-status` в `exclude`. Мод грузится при старте сессии.
Механика модов — `<kit>/knowledge/claude-code-mods.md`.
