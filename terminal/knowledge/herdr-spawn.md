# herdr: завести несколько сессий Claude под задачи

Когда владелец просит разложить пачку задач по отдельным сессиям («на каждую задачу — своя сессия,
пусть запускают разработку»). Проверено 21.10.2026: пять сессий из одной координирующей.

## Порядок

1. **Бриф — файлом**, промпт — одной строкой со ссылкой на него. В брифе: кто чем занят (таблица
   «сессия — задачи»), общие правила (свой worktree, где журнал, что нельзя без владельца), особенности
   каждой сессии. Сессии читают его сами, координатор не пересказывает в промптах.
2. **Вкладка** — `herdr tab create --workspace "$HERDR_WORKSPACE_ID" --cwd <каталог> --label "<ID> <название>"
   --no-focus`; id панели — `.result.root_pane.pane_id`. Метка, заданная так, — ручная: автоименование её
   не трогает. Формат метки — `herdr-naming.md`.
3. **Агент** — `herdr agent start <имя> --kind claude --pane <pane_id> --timeout 90000 -- <аргументы>`.
   Имя — `[a-z][a-z0-9_-]{0,31}`, уникальное среди живых. Аргументы — те же, с которыми владелец запускает
   `claude` на этой машине (подсмотреть в `ps -axo args | grep claude`), иначе сессия не получит, например,
   каналы. Возвращается, когда агент готов к вводу; модель, effort и режим разрешений — из настроек
   по умолчанию.
4. **Промпт** — `~/.claude/bin/claude-prompt <имя> "<одна строка>"` (обёртка над `herdr agent prompt`,
   `tools.md`). У `herdr agent prompt` `--timeout` работает только вместе с `--wait`, без него — ошибка.
5. **Проверка старта** — `herdr agent wait <имя> --until working --timeout 20000`, затем
   `herdr agent read <имя> --source visible`: нет ли диалога на экране.
6. **Пометка уже работающей сессии** — тем же `claude-prompt`: Claude Code ставит её в очередь и
   прочитает после текущего шага.

## На что смотреть

- **Общие ресурсы — в бриф заранее.** Диск: один worktree с `node_modules` весит гигабайты; пять сессий
  за час съели 18 ГБ из 24 свободных. Нужен порог («меньше N ГБ — зависимости не ставить») и запрет
  удалять чужое ради места.
- Статус всех вкладок — `herdr tab list --workspace "$HERDR_WORKSPACE_ID"` (`agent_status`); `done`
  значит, что ход закончен и не просмотрен, а не что задача сделана: сессия может ждать фоновую сборку.
- **Фоновый сторож координатора** — петля в фоне Bash: выходит (и будит координатора), когда свободного места
  меньше порога или у вкладки `agent_status == "blocked"`, иначе — раз в ~час. На `idle` и `done` не срабатывать:
  `idle` бывает просто после сжатия сессии, `done` — у каждой, кто ждёт фоновую сборку (21.10.2026: будил зря).
- **Строка ввода в `herdr agent read`** может показывать серую подсказку Claude Code («сними Draft и отправь на
  ревью»): это не набранный текст и не решение владельца — не считать её командой. Подсказка про необратимое —
  сказать владельцу, чтобы не принял её случайно.
- Общий лимит внешних ресурсов (стенды на автора, слоты сборки) — в бриф заранее, как и диск; что освободить,
  решает владелец — координатор спрашивает его кнопками, сессии ждут.
- Не закрывать вкладки и панели, которые завела не эта сессия.
- **Обратная связь — от сессии координатору.** Имя агента-адресата — `herdr agent list` (`name`; рядом
  `agent_session.value` — id сессии и `tab_id` — вкладка), письмо — тем же `claude-prompt <имя> "<строка>"`; ответ
  придёт как обычный промпт. Так рабочая сессия отдаёт координатору общий ресурс, который сама решать не должна
  (лимит стендов на автора, чужой стенд), а не ждёт владельца молча (21.10.2026).
