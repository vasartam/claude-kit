# Перезапуск сессии на месте

Утилита `~/.claude/bin/claude-restart` (исходник — `<kit>/terminal/bin/claude-restart`) сама
отвязывается от вызвавшего процесса, дожидается, пока агент закончит ход, шлёт claude SIGTERM
и в той же панели запускает `claude --resume <тот же id>` с прежними флагами. Вкладка, разговор,
имя агента в herdr, расписание и фоновые задачи сохраняются (см. ниже); журнал —
`~/.config/herdr/claude-restart.log`.

Работает только внутри herdr (`HERDR_ENV=1`). Вне его — сказать, что перезапуск на месте
недоступен, и предложить `/exit` и `claude --resume <id>` руками.

## Что запускать

| Просьба | Команда |
|---|---|
| перезапустить эту сессию | `~/.claude/bin/claude-restart` |
| все панели на удалённом файле программы (голос умер после обновления) | `~/.claude/bin/claude-restart --stale` (сначала `--dry-run --stale`, показать список из журнала) |
| конкретную панель | `~/.claude/bin/claude-restart <pane-id>` |
| с раскладкой знаний перед перезапуском | добавить `--knowledge` (по умолчанию выключено: `--resume` возвращает разговор целиком) |

Команда возвращается сразу. Перезапуск **этой** сессии начнётся после конца хода, поэтому
после вызова больше ничего не делать: ответить одной строкой и закончить ход.

`--stale` перезапускает только панели, где у процесса claude удалён или подменён файл программы
(так бывает после обновления npm-установки; нативный установщик файлы живых версий не удаляет).
Каждая панель ждёт конца своего хода до 10 минут. Почему на macOS у таких процессов умирает голос —
`<kit>/macos/knowledge/voice.md`.

## Что переживает перезапуск

Проверено 25.09.2026 на Claude Code 2.1.282 e2e-тестом в панели herdr.

| Что | Как возвращается |
|---|---|
| задания CronCreate (разовые и повторяющиеся, `/loop` с интервалом) | `--resume` восстанавливает их сам, срабатывают по прежнему расписанию |
| будильник `/loop` без интервала (ScheduleWakeup) | теряется; утилита дожидается его срока и отправляет агенту тот же промпт |
| фоновые Bash-команды, мониторы, фоновые субагенты | гибнут; их список уходит новому процессу первым промптом, агент перезапускает нужные, а разовые команды с побочными эффектами сначала проверяет |
| черновик в поле ввода | теряется, поэтому перезапуск ждёт конца хода |
| разрешения «на эту сессию» | могут потребоваться заново |

Если перед перезапуском (`--knowledge`) приходит `/session-extract-knowledge` с пометкой про
claude-restart — разложить знания и **не прощаться**: разговор продолжится. Если после перезапуска
приходит промпт «Перезапусти фоновые задачи, которые остановил перезапуск сессии (claude-restart)…» —
это и есть передача от утилиты, её нужно выполнить.

Хоткей того же действия для панели в фокусе — `Ctrl+Shift+R` в herdr (настройка —
`<kit>/terminal/knowledge/hotkeys.md`). Фоновую сессию (`claude attach …`) утилита не перезапускает,
свои флаги машины (каналы и т. п.) — в `~/.claude/claude-restart.local.zsh`; подробно —
`<kit>/terminal/knowledge/restart-in-place.md`.
