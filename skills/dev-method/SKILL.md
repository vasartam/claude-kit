# Методология разработки

Правила выросли из ошибок; «почему» — в `references/`. Переноси структуру, не
чужие имена и пороги. Образцы — [references/examples.md](references/examples.md). В чужом
репозитории его регламенты главнее: устройство docs и процесс — оттуда, остальное — отсюда.

## 1. Документация — часть изменения

- Документы — **в том же коммите, что код**, без напоминаний. «Что изменилось → куда
  записать»: кратко — в `AGENTS.md`, полно — в `docs/README.md`; новый документ — строкой в
  `README.md` его папки.
- Решение — с причиной и отвергнутыми вариантами; писать невидимое из кода;
  устаревшее зачёркивать. Статус (`docs/log/status.md`) — сделано / не закончено / **не
  проверено и почему**.
- **Агент читает только нужное**: `AGENTS.md` 2–3 КБ с индексом; в папках `docs/` —
  `README.md`, строка на файл; статус — только открытое.

Подробно — [references/documentation.md](references/documentation.md).

## 2. Мерить, а не прикидывать

Число — с методикой, выборкой, медианой и разбросом, фоном; узкое место — замером. Прикидки
помечать; «не проверено» — отдельный вывод; один объект — наблюдение, не замер; чужую
платформу — по схеме API и исходникам. Подробно — [references/measurement.md](references/measurement.md).

## 3. Любой баг → сначала тест, падающий на старом коде

Каждый баг, до фикса: настоящая причина → юнит-тест (логика), сценарный тест от
экрана, где баг виден (интерфейс), или кейс самопроверки (внешний мир) → **проверка падает на
старом коде** → фикс итерациями до зелёного → запись в `docs/log/regression-cases.md` словами
пользователя. Закрыт — когда исправление увидел сам: зелёный прогон, для интерфейса и живой
браузер. Тест зовёт ту же точку входа, что приложение; эталон — ground truth. Повторяющаяся
ошибка — по классу: запрос по признаку → починить всё → тот же запрос пуст. Подробно —
[references/testing.md](references/testing.md).

## 4. Новая фича — с исследования и плана проверки

План, потом код: задача и связанные, закрытые MR с диффом, код и его история, тесты,
контракты, метрики, docs, готовые навыки и свои инструменты — до предложения новых. В дизайне —
как проверить: что наблюдаемо снаружи, чем включается точечно, откуда данные, если сосед не
готов; проверка — запрос с ожидаемым ответом. Экран — после самопроверки
(`/screen-selfcheck`). Подробно — [references/features.md](references/features.md).

## 5. Чистые функции отдельно от ввода-вывода

Решения и форматирование — чистые функции с юнит-тестами; тесты без сети, часа, пояса, даты.
«Пишет — читает» — тестом на стык; хотя бы один тест с настоящей внешней программой; кэш не
меняет результат; зависимость не со всех машин — вне lock-файла. Подробно —
[references/testing.md](references/testing.md).

## 6. Деплой и автоматика

Только CI после зелёных тестов; ручной путь — аварийный, в `docs/ops/deploy.md`. Откат,
здоровье по настоящему признаку работы, идемпотентные шаги, секреты вне git, у CI минимум
прав. Автоматика зависла после сбоя — детектор с уборкой и сообщением, а не короткий таймаут;
фоновая петля без человека UI не трогает. Подробно —
[references/operations.md](references/operations.md).

## 7. Работа агентов

- Маленькие коммиты (код + документация + тест) агент делает и пушит сам; крупная побочная
  задача — субагенту в worktree с перечнем **его** файлов. Наружу — только с пометкой «тест»;
  частный случай правим в частном случае; голос владельца — словарь в `AGENTS.md`.
- **Грабли**: агент падает молча — проверь работу в ветке; подписывать числа; убирая
  интерфейс — `grep` по зовущим; оптимизация ломает допущения соседей; чужое незакоммиченное —
  отдельным коммитом до своих.
- **Неслитая ветка на стенде** — своя папка, свой тег образа, прод не трогать, записать возврат.
- **Чего агент проверить не может** — назвать и дать владельцу одно действие на остаток.

Подробно — [references/agents.md](references/agents.md). Git (rebase, конфликты) —
`knowledge/git-workflow.md` набора.

## 8. Чеклист перед словом «готово»

Тесты зелёные; линтер и формат чистые; саморевью по коммитам до push; документация — в этом
же изменении; баг закрыт тестом, падавшим на старом коде; проверено живьём
(снимки и разметка — в MR) или записано, почему нет; статус дописан; коммит запушен.

## 9. Навык поддерживается по ходу работы

Новое правило или грабля — сюда в том же изменении: суть — в `SKILL.md` (≤ ~8 КБ),
подробности — в `references/`; частность проекта — в его docs. Живёт в `<kit>/skills/dev-method`,
без копий в проектах.
