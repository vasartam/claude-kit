# Память деревом

Когда память Claude Code (память проекта `~/.claude/projects/<папка>/memory/` или общий
каталог из настройки `autoMemoryDirectory`) разрастается, плоский индекс перестаёт помещаться.
Тогда — дерево разделов.

## Пределы сканера памяти

Проверено по бинарнику Claude Code 2.1.282, 25.09.2026:

- каталог обходится рекурсивно; записи — все `*.md`, кроме файлов с именем `MEMORY.md` на
  любой глубине. Индекс с другим именем (`_index.md`, `INDEX.md`) попадёт в список как запись
  без frontmatter;
- не больше **200 файлов**, свежие по mtime первыми — у предела сливать близкие записи, а не
  плодить новые;
- корневой `MEMORY.md` грузится в каждую сессию и обрезается на ~24,4 КБ: хвост теряется
  молча (плоский индекс на 166 строк дорос до 29 КБ — отсюда и дерево).

## Раскладка

- **Корневой `MEMORY.md`** — только правила, которые действуют в любом ответе, и строка на
  раздел: `- [git](git/MEMORY.md) — раздел: ветки, коммиты, ревью`. Держать до ~17 КБ.
- **Раздел** — подпапка темы со своим `MEMORY.md`: строка на запись
  `- [slug](slug.md) — крючок` (3–8 слов, подробности — в файле), ссылки относительные.
- **Новая запись:** раздел по строкам корня → `<раздел>/<slug>.md` (frontmatter `name`,
  `description`, `metadata.type`) → строка в `<раздел>/MEMORY.md`. Встроенное «добавь строку в
  `MEMORY.md`» значит индекс раздела, не корень. Подходящего раздела нет — папка с `MEMORY.md`
  и строка в корне. В корень — только то, что должно срабатывать без чтения раздела.
- Ссылки `[[slug]]` — по имени: перенос записи между разделами их не ломает.
- Дубли искать по всему дереву, не только по корню: `rg -l -i --hidden --no-ignore "<запрос>"
  <каталог>` — каталоги памяти часто скрытые, без флагов rg их пропускает и пустой ответ
  выглядит как «записи нет» (так однажды завелась вторая запись о только что обновлённом файле).
