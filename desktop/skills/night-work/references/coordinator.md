# Координатор ночной работы

Часть навыка night-work для сессии-координатора (кто им становится — SKILL.md, «Роли и реестр»). Реестр, статусы и цикл исполнителя — в SKILL.md.

## Старт (координатор, пока владелец ещё у компьютера)

1. `get_usage` → исходные проценты и сброс в `README.md`.
2. `list_sessions` → исполнители: названные владельцем и сессии с незаконченной работой, о
   которой он говорил. Архивные и чужие не трогать; сессии планировщика сообщений не
   принимают — их не координировать.
3. **Режим разрешений:** у владельца все сессии по умолчанию в `auto` — только сверить
   (`permissionMode` в реестре исполнителя). Если какая-то в `default`/`acceptEdits` —
   сказать владельцу: ночью она встанет на первом вопросе, а сообщения других сессий будут
   ждать одобрения. Самому не менять.
4. **Effort исполнителей** — `set_session_effort` по задаче: исследование, архитектура,
   большой рефакторинг, трудная отладка → `max`; обычная разработка → `xhigh`; механика
   (документация, прогон проверок, мелкие правки) → `high`. Выше своего уровня и для
   сессий, запущенных не координатором, приложение спрашивает владельца — поэтому только
   сейчас, пока он у компьютера; ночью effort не менять (вопрос повиснет до утра). Уровень —
   в реестр исполнителя и в список для владельца (п. 10).
5. Каждому исполнителю — [стартовое сообщение](kickoff.md) через `SendMessage`
   (`to` — `local_…` id; нужен статус доставки — `send_message`, он отвечает delivered/queued).
6. **Проверка запуска** через 5–10 минут: у каждого — файл реестра со статусом `working` и id
   будильника. Нет → `list_events` (`limit: 5`) этой сессии: ждёт разрешения, сообщение
   задержано, не загрузил навык? Сказать владельцу **до ухода**, что поправить.
7. **Сон компьютера — только проверить:** сон по таймеру выключен (Windows —
   `powercfg /query SCHEME_CURRENT SUB_SLEEP`, значение 0; macOS — `pmset -g`, `sleep 0`), нет
   ожидающей перезагрузки после обновлений. Менять — владельцу. Предупредить: закрытие или
   перезапуск приложения и перезагрузка компьютера стирают все будильники — ночная работа
   встанет до утра.
8. Свой контрольный будильник: `CronCreate` recurring `"7 * * * *"` (раз в час), промпт:
   «Проверка ночной работы по навыкам night-work и limit-guard, реестр <папка>». Отдельный
   будильник limit-guard не ставить — его проверка идёт в этом же ходе, реестр — `README.md` ночи.
   Сразу — отметка жизни (п. 1 проверки ниже).
9. По желанию владельца — **утренняя страховка** на случай перезапуска приложения:
   `create_scheduled_task` с `fireAt` = утро + 10 минут (ISO с `+03:00`): «если в
   `<папка>/README.md` нет утренней сводки — составить её по файлам реестра и отчётам;
   `PushNotification`, если что-то ждёт владельца». Будить сессии она не может.
10. Коротко владельцу: кто исполнители, когда отчёт, что уже собрано на утро.

## Проверка координатора (раз в час)

1. Отметка жизни — Bash
   `mkdir -p ~/.claude/limit-guard && date > ~/.claude/limit-guard/alive-night-work`: пока файлу
   меньше 75 мин, хук `limit-guard` в сессиях молчит — паузы и пробуждения ведёт координатор,
   второго пробуждения от хука не будет.
2. Проверка по навыку limit-guard: 85/90 % — предупреждение и просьба о паузе только
   **не ночным** работающим сессиям (исполнители встают сами); при ≥ 90 % — два будильника
   пробуждения limit-guard (сброс + 4 и + 15 минут), они будят и исполнителей, если их
   собственный будильник не сработал. 5 ч ≥ 90 % → дальше никого не будить, строка в README, конец.
3. По файлам реестра:
   - `working`, файл не обновлялся > 45 минут → `ListAgents`: сессия занята — не трогать;
     свободна → `list_events` (`limit: 5`): ошибка лимита, обрыв, конец хода без записи →
     разбудить: «Продолжай ночную работу по навыку night-work, реестр …».
   - `paused`, время пробуждения прошло больше 20 минут назад, а файл не обновился
     (будильник, видимо, пропал) → разбудить так же.
   - `blocked`/`done` — не трогать.
4. Строка в `README.md`: время, проценты, кого будил.

## Утренняя сводка

- **Координатор**, когда все `done`/`blocked` или утро: сводка в `README.md` —
  `| Сессия | Состояние | Главное | Ждёт владельца | Отчёт |`, затем общий список «Ждёт
  владельца», строка «Лимит за ночь: паузы (с–по), неделя было → стало»; снять свой
  будильник и удалить `alive-night-work` (паузы снова ведёт хук); выжимка в чат;
  `PushNotification` — только если что-то ждёт действия владельца.
