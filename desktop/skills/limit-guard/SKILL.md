# Координатор лимита

Лимит тарифа **общий**: все сессии Claude Code и чат claude.ai. Без присмотра сессии доедают
его до 100 %, обрываются посреди шага, а владельцу не остаётся ничего на свои задачи в чате.
Поэтому пауза — раньше потолка: запас владельцу ~10 % каждого окна. Родилось 26.09.2026: в
18:07 лимит был 92 %, сессии работали дальше.

Нужны инструменты приложения `mcp__ccd_session_mgmt__*` (`get_session`, `get_usage`,
`list_sessions`, `list_events`, `send_message`; отложенные — сначала ToolSearch) и `CronCreate`.
В Claude Code из терминала их нет — там навык не применять.

Координатор **сам работы не берёт** (его будильники срабатывают только в свободной сессии), он
один на все сессии и пишет владельцу коротко: кого поставил на паузу, кого разбудил.

## Пороги

| Окно | Предупреждение | Пауза | Продолжение |
|---|---|---|---|
| 5 часов (`5-hour limit`) | 85 % | 90 % | после сброса окна |
| неделя (большее из `Weekly · all models` и недельного окна модели) | 85 % | 90 % | после недельного сброса |

Владелец назвал другие числа — записать их в реестр и держаться их. Переключение на Fable
неделю не бережёт: `Weekly · Fable` — потолок внутри общего окна (`knowledge/claude-models.md`).

## Старт

1. `get_session self` → свой `sessionId`. Реестр — один файл `~/.claude/limit-guard/registry.md`
   (недельная пауза длится днями, поэтому не по датам). Там уже есть живой координатор (запись
   за последний час, сессия не архивная) — второй не нужен: сказать владельцу, кто координирует,
   конец. Идёт ночная работа — записи в `README.md` ночи из night-work (строки — в конец, `>>`),
   отдельный реестр не нужен.
2. В реестр: координатор, пороги, id будильников и **дата создания** recurring, таблица
   `| Сессия | id | На паузе с | Окно (5ч/неделя) | Состояние |`, «Журнал» — новые сверху, строка
   на проверку: `ДД.ММ ЧЧ:ММ | 5ч N % / неделя M % | что сделал`; больше ~200 строк — старое в
   `archive-<ГГГГ-ММ>.md`.
3. `get_usage` и сразу — проверка ниже.
4. Будильник проверки — `CronCreate` recurring `"7,27,47 * * * *"`, промпт: «Проверка лимита по
   навыку limit-guard, реестр <путь>». Сказать владельцу: будильники живут, пока открыто
   приложение (после перезапуска — написать координатору что угодно); recurring сам пропадает
   через 7 дней (пересоздать — проверка, п. 1).

## Любой ход координатора — сначала `CronList`

Будильники живут только в памяти приложения: перезапуск приложения или компьютера стирает их,
переписка и реестр остаются. Поэтому любой ход (будильник или сообщение владельца) начинается с
`CronList`: будильника проверки нет, а координатор в реестре — эта сессия → пересоздать его и
будильники пробуждения для сессий на паузе, id — в реестр, владельцу строка «будильники
восстановлены». Пропущенный сброс не страшен: первая же проверка его увидит. Без владельца
не выйдет: рутина переживает перезапуск, но писать в сессии ей нельзя
(`desktop/knowledge/claude-desktop-restart.md`).

## Проверка (каждый будильник)

1. Отметка жизни — Bash `date > ~/.claude/limit-guard/alive-limit-guard`: пока файлу < 30 мин, хук
   `limit-guard` в сессиях молчит. `get_usage`, строка в журнал. Recurring старше 6 дней — создать
   новый, старый снять.
2. **Продолжение:** в реестре есть сессии на паузе, их окно уже ниже порога предупреждения
   (сброс прошёл), а второе окно ниже порога паузы → разбудить по
   [references/wake.md](references/wake.md). Так продолжение не зависит от одного будильника.
3. **Пауза и предупреждение** — по таблице порогов, только **работающим** (`isRunning: true`),
   каждой — один раз за окно (сессию, которую владелец сам продолжил на паузе, не трогать).
   Кому и как писать, тексты — [references/messages.md](references/messages.md); тон мягкий:
   работу не бросать, довести до удобной точки. Кто и когда встал — в реестр.
4. При паузе — будильники пробуждения на сброс окна: **два одноразовых**, `resetsAt + 4 мин`
   и `+ 15 мин` (одноразовый точен, повторяющийся опаздывает до 15 минут; оба идемпотентны;
   время — wake.md). Для недели — так же, дата полностью. Недельная пауза — ещё
   `PushNotification`: «недельный лимит N %, сессии на паузе до <дата ЧЧ:ММ>».

## Конец

Владелец сказал «хватит» — `CronDelete` своих будильников, удалить `alive-limit-guard` (паузы снова
ведёт хук), итог в реестр и одной строкой в чат.
Сессии на паузе остаются как есть — сказать владельцу, какие.
