# Приложение Claude (вкладка Code): перезапуск, сон, будильники, рутины

Проверено 26.09.2026 на Windows, приложение 2.7032, CLI 2.1.280 — логами приложения, пробными
запусками и чтением кода приложения; пути macOS сверены 03.10.2026. Зачем: навыкам limit-guard
и night-work нужно пережить перезапуск компьютера без владельца.

## Что пропадает и что остаётся

- **`CronCreate` живёт только в памяти процесса сессии.** Перезапуск приложения или компьютера
  его стирает. Приложение это видит и только пишет в лог: «N restored session(s) lost /loop or
  background work to the previous quit», само не восстанавливает. Параметр `durable` в
  нашей сборке выключен («durable persistence is not available»). «Начни сам через N часов» —
  такой же разовый будильник: живёт, пока жив процесс сессии.
- **Процесс сессии** живёт, пока открыто приложение (дни). Запускается, когда сессию открыли
  в окне («Warming session» при фокусе) или прислали ей сообщение (cold start с `--resume`). Сам
  по себе после старта приложения — нет. Сон, закрытая крышка, выключение и перезагрузка (в том
  числе для обновлений ОС) обрывают работу сессии и удалённое управление.
- **Рутины** (Routines, `create_scheduled_task`) хранятся на диске, `cwd` — папка создавшей
  сессии; пропущенный запуск выполняется при следующем старте приложения. Каждый запуск —
  **новая** сессия «unattended»: `get_usage`, `list_sessions`, `list_events` работают, а
  `send_message`/`SendMessage` в другие сессии, окна и настройки запрещены приложением.
- **Без автозапуска приложения при входе в систему** после перезагрузки не работает ничего, пока
  приложение не открыто. Включается в автозагрузке ОС или в настройках приложения.

## Что может начать ход в существующей сессии

Только: сообщение владельца (в окне или с телефона через Remote Control — переключатель в
самой сессии), `send_message` из **обычной** (attended) сессии, будильник этой же сессии, и
встроенные автопродолжения:

- **после сна**: ход шёл, компьютер уснул → по пробуждению приложение само пишет «My computer
  went to sleep while you were working. Please continue from where you left off.»;
- **после закрытия**: ход шёл, приложение закрыли → при следующем запуске «The app was quit
  while you were working…» — за серверным флагом; у владельца, судя по логам, не срабатывало.

Оба — только для сессий, у которых **шёл ход**; простаивающую сессию с будильниками не
продолжают.

**Не работает** (проверено): хук `SessionStart` с `asyncRewake: true` — приложение ждёт его
синхронно (старт сессии затянулся на время хука), код 2 модель не будит. `asyncRewake` будит
только из хуков внутри живого процесса. Deep link `claude://claude.ai/epitaxy/<local_id>`
только открывает сессию в окне (текста не передаёт). Отдельный `claude` CLI не делит вход с
приложением (`Not logged in` без своего `/login`).

## Прочее

- Джиттер `CronCreate`: повторяющийся может опоздать до 10 % периода (до 15 минут), поэтому
  «пробуждение к сбросу» ставить **одноразовым** с полной датой — он точный (±90 с только на
  :00/:30). 26.09 повторяющийся на 19:04 «не сработал»: опоздание, а в 19:12 его сняли.
- Логи приложения — `main.log` (старые — `main1.log`): Windows — `%LOCALAPPDATA%\Claude\logs\`,
  macOS — `~/Library/Logs/Claude/`. Там видно запуск/остановку сессий, будильники («cron …
  confirmed (active: N)»), простой.
- Настройки сессий приложения — `claude-code-sessions\<account>\<org>\local_*.json` в
  `%APPDATA%\Claude\` (Windows) или `~/Library/Application Support/Claude/` (macOS; там же
  `scheduled-tasks.json` рутин). `cliSessionId` — id сессии CLI, файл переписки —
  `~/.claude/projects/<cwd>/<cliSessionId>.jsonl`.
