# Приложение Claude (вкладка Code): окружение, сеть, effort, просмотр изменений

Что отличает вкладку Code в приложении от `claude` в терминале. Перезапуск, сон и будильники —
`claude-desktop-restart.md`.

## Окружение и вход

Проверено 25.09.2026 на macOS (приложение 2.9939.2, встроенный Claude Code 2.1.281).

- `env` из `~/.claude/settings.json` применяется (например, `ANTHROPIC_CUSTOM_HEADERS` доходит),
  **но `ANTHROPIC_BASE_URL` приложение перезаписывает на `https://api.anthropic.com`** уже после
  чтения настроек: вкладка Code входит OAuth-сессией самого приложения
  (`CLAUDE_CODE_SDK_HAS_HOST_AUTH_REFRESH=1`), её токены годятся только для официального адреса.
  Свой шлюз или base URL в настройках действует только на `claude` из терминала.
- `NO_PROXY` приложение тоже перезаписывает — на `localhost,127.0.0.1,::1,.local`: исключения из
  `settings.json` во вкладке Code не действуют, остальные адреса идут через прокси.
- Прокси (`HTTP_PROXY`/`HTTPS_PROXY`) дочерним процессам выставляет само приложение — из
  системных настроек прокси, в том числе PAC; руками задавать не нужно.
- **Свой Claude Code у приложения** — `%APPDATA%\Claude\claude-code\<версия>\<хэш>\claude.exe`
  (Windows), обновляется вместе с приложением; `claude` в PATH может быть сильно старше (04.10.2026
  дома: в PATH 2.1.81 без `claude plugin test`, у приложения 2.1.286). Проверки, которые должны
  совпасть с поведением вкладки Code (`claude plugin test` модов), — этим бинарём.
- Прокси, жёстко прописанный в `env` файла `settings.json`, действует и там, где этот прокси
  недоступен (другая сеть) — сессии тогда без связи.
- PATH у приложения свой — без каталогов, которые добавляют профиль оболочки или программа,
  запускающая терминальный `claude`. Хук, который зовёт утилиту по имени, может её не найти и
  молча отработать вхолостую (случай 10.08.2026: хук отдавал пустой контекст). Звать по полному
  пути или класть ссылку в каталог, который есть в PATH и приложения, и терминала (на macOS —
  `~/.local/bin`).
- Отдельный `claude` из терминала не делит вход с приложением (`claude-desktop-restart.md`).

## Effort

- Подхватывает ли приложение `"effortLevel"` из `~/.claude/settings.json` — не проверено.
- Свой effort сессия менять не может: `set_session_effort` на себя отказывает. Другой сессии —
  выше своего уровня или не своей — только с подтверждения владельца.

## Окно и телефон

- Кнопка просмотра изменений показывает только файлы внутри рабочей папки сессии — работу с
  проектом начинать в его папке.
- Удалённое управление (Remote Control, с телефона) — переключателем в самой сессии; живёт,
  пока жива сессия (`claude-desktop-restart.md`). Настройка «Connect new sessions to Remote
  Control» подключает только запущенные сессии; спящую (после перезапуска приложения)
  `set_remote_control` не включает: «requires an active session. Send a message first».
- Разбудить спящую сессию и вывести её на телефон: из обычной сессии `send_message` («ответь
  «Ок», ничего не делай»), сразу `set_remote_control` — on. Замер 08.10.2026: холодный старт
  сессии с контекстом 92k — 5-часовой лимит Max не сдвинулся с 2 %; процесс сессии ~300 МБ
  ОЗУ и живёт до закрытия приложения. Поэтому всех разом не будить (45 сессий ≈ 14 ГБ), а
  держать на телефоне одну сессию и будить из неё нужные по просьбе.
- `run_in_terminal` (панель терминала) может не открыть вкладку: «Claude terminal integration did
  not load … terminal-shell-integration\pwsh\claude-desktop.ps1» — оболочка не доходит до
  приглашения за 60 с (07.10.2026). Интерактивное (вход по QR, коды) тогда — одной строкой
  владельцу в его терминал.
