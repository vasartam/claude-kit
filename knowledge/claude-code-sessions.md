# Claude Code: сессии — effort, workflow, облако, имена

## Effort, workflow, ultracode

- **Effort** (low/medium/high/xhigh/max) — глубина мысли агента. По умолчанию —
  `"effortLevel": "high"` в `~/.claude/settings.json`; выбор в `/effort` пишется туда же по
  модели (`modelSettings.<модель>.effortLevel`). Сабагент на Sonnet без явного effort работает
  с `medium`, у Haiku effort нет. Как сессия узнаёт свои модель и effort — правила слоя;
  таблица «модель и effort под задачу» — `claude-models.md`.
- **Workflow** — скрипт сессии, раздающий работу многим субагентам (параллельный обход,
  опровергающие проверки, «пока находится новое»); от effort не зависит. Запуск — только по
  явной просьбе («через workflow», слово `ultracode`) или из вызванного владельцем навыка.
- **Ultracode** — опция поверх любого effort (`/effort ultracode on|off`, в пикере `/effort` —
  клавиша Tab): постоянное разрешение на workflow для каждой существенной задачи без оглядки на
  токены. Действует **на одну сессию** («this session only»): выключение в одной вкладке другие
  не трогает. Где его видно — `claude-code-context.md`. Автовключение по остатку лимитов
  владелец отклонил (26.09.2026): решать под конкретную задачу.

## Версия процесса

Обновление Claude Code не доезжает до идущих сессий: процесс работает на версии своего старта.
«Работает только в новой сессии» — сначала сверить версию процесса (как —
`terminal/knowledge/updates.md`), а не искать причину в правах и настройках.

## Облачные сессии и GitLab

Документация, 27.09.2026. Клонирование и PR — только GitHub. Репозиторий с GitLab уходит в
облако лишь как bundle (`CCR_FORCE_BUNDLE=1`), и облачная сессия не может запушить результат
обратно; забрать работу — `claude --teleport` в локальный терминал и push оттуда. Облачные
сессии делят лимиты тарифа со всем остальным.

## Имена сессий

Claude Code сам даёт сессии kebab-имя (отдельный запрос к модели, `rename_generate_name`; в
транскрипте `{"type":"agent-name",…}`), отключить нельзя. Это то же имя, что задают `-n/--name`
и `/rename`; оно важнее ИИ-заголовка везде, и `ai-title` после него больше не обновляется.
Реестр — `~/.claude/sessions/<pid>.json` (`pid`, `sessionId`, `cwd`, `name`): по нему `ListAgents`
показывает, а `SendMessage` адресует сессии. Без имени сессия зовётся `<хост>-XX` и тоже
адресуется. Правка файла реестра на живой процесс не действует, внешнего API переименования
нет (2.1.246).

## Правила

- **Свои сессии называть по-русски** обычными словами, 2–6 слов, суть задачи (ключ задачи или
  номер MR — в конце): «Разбор падения сборки», а не `build-failure`. Касается всего, где имя
  задаю я: `-n/--name`, `/rename`, вкладка терминала, облачная или фоновая сессия, имя для
  `SendMessage`. *Почему:* владелец ищет вкладки и `/resume` по этим именам (26.09.2026).
  Автоимя Claude Code этим не чинится.
- **Тик лупа** (`/loop`, будильник, наблюдение за сборкой) кончается видимой сводкой: что
  изменилось и нужно ли владельцу что-то сделать (🔴 — с действием и ссылкой, иначе «от тебя
  ничего не нужно»); незакрытые 🔴 повторять кратко, пока их не закрыли. «Следующая проверка в
  HH:MM» — только в конце сводки, никогда отдельным последним сообщением. *Почему:* владелец
  (28.09.2026): «почему ты просто пишешь следующая проверка… мне нужно вообще на что-то
  реагировать?».
