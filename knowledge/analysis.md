# Анализ данных: не обмануть себя

- **Целостность данных — до любых выводов.** Откуда взято каждое значение, существует ли id на
  самом деле, совпадают ли независимые пути получения. *Случай:* «кучность» и «повторы» с
  безупречной статистикой (перетасовки 0/200, +25 % ROI на обеих половинах) оказались
  фантомными id собственного сборщика — сайт нумеровал раунды через один.
- **Идею владельца разворачивать в перебор переменных**, а не проверять одну точку.
- Итог — честный, в том числе «преимущества нет».
- Утверждения о картинке, кадре, поведении алгоритма — прогоном на реальных данных с числами;
  догадки помечать (`owner.md`). Числа — по методике навыка `dev-method` (раздел «Мерить»).
- Долгий прогон, скан, выгрузка сохраняют результат **по ходу, пачками**, а не в конце: сессия
  перезапускается, вкладка браузера закрывается — и всё, что было в памяти, пропадает. Сырой
  вывод — всегда в файл.
- **Поиск стратегии или параметров по истории** — протокол: всё числовое и выборное — в
  параметры, сетка шире предложенной; подбор на первой половине, оценка на второй (место
  лучшего, средний результат топ-10 на проверке); ранговая корреляция (Спирмен) результатов
  вариантов между половинами — около нуля значит, что подбор ловил шум; перетасовка — доля
  прогонов «не хуже факта»; **нулевой перебор** — весь перебор на нескольких перетасованных
  наборах показывает, какой «лучший плюс» даёт одно везение. Сравнивать с эталоном на тех же
  данных (слепая стратегия), а не с теорией.
- **Много срезов — множественные сравнения**: q по Бенджамини–Хохбергу < 0,05 плюс один знак и
  |z| ≥ 2 на обеих половинах; сверить число «p < 0,05 без поправки» с ожидаемыми ~5 %.
  Вложенные пороги (N = 34…44) дают пачку ложных сигналов из одного везения.
- **Предрегистрация**: выживший кандидат проверяется только на данных, которых не было в
  анализе; гипотезу, данные, объём и критерий записать до проверки и задним числом не менять; на
  удачном промежуточном итоге не останавливаться. Реальные деньги — только после неё.
- Прогрессии ставки (мартингейл и т. п.): учитывать сливы банка; их средний результат по
  перетасовкам смещён вверх — критерий — доля прогонов «не хуже».
- **Доля успехов — с полным знаменателем**: провалы считать по независимому признаку, а не по
  тому, что видно только у успехов. *Случай:* отчёт «14 из 16 успешно» по надписям успеха; по
  признаку провала — провалено около 9 из 22.
- **Хранить источник каждого значения** (живое наблюдение / список истории / вычислено).
  `INSERT OR IGNORE` навсегда закрепляет первое, возможно устаревшее значение; идентификатор не
  вычислять догадкой («последний + 1») — брать у источника; эффекты считать по записям с
  надёжным источником.
