# Claude Code: права и классификатор auto mode

## Правила `permissions`

- У правил `Bash(...)` два синтаксиса: старый `Bash(<префикс>:*)` — «команда начинается с
  префикса, дальше любые аргументы», новый `Bash(<шаблон>)` — `*` как маска в любом месте
  (`Bash(~/.claude/bin/*)`). **Смешивать нельзя**: `Bash(~/.claude/bin/*:*)` читается как
  литерал и ничего не разрешает; при запуске — жёлтое предупреждение `… mixes * with the
  trailing :* prefix syntax` (25.09.2026).
- Запущенный из `~` Claude Code читает `~/.claude/settings.json` и как пользовательский, и как
  проектный — каждое предупреждение о нём выводится дважды; это не две ошибки.
- `Write(...)` в файловых проверках не участвует («only Edit(path) rules are»).
- Свои правила агент не правит (запрет классификатора, ниже); исправление — владельцу одной
  строкой.

## Классификатор auto mode

- Проверок две, и они независимы: правила `permissions` (`Bash(*)` разрешает всё) и
  **классификатор** поверх них — модель, которая смотрит на смысл действия и блокирует, даже
  когда правила разрешают.
- **Режет** (24.08–01.10.2026):
  - вывод секретов: чтение `~/.claude.json` с токенами MCP — даже имён ключей `env`; JS в
    браузере, ищущий токены (`claude-in-chrome.md`);
  - правку своих прав (`permissions.allow`, `autoMode` в `settings.json`) и запись скрипта,
    который их правит [Self-Modification] — пока владелец сам не попросит написать такой скрипт;
    подключение своих хуков и навыков (`scripts/link.py` правит `hooks` в `settings.json`, 03.10.2026) —
    тоже: скрипт в файл, владельцу одна строка `! zsh <файл>`;
  - `rm -rf` каталога [Irreversible Local Destruction] — обход: `mv` в резервную папку рядом,
    `rm` оставить человеку;
  - чтение прод-данных («Production Reads») и деплой — пока владелец явно не попросил;
  - иногда — запуск скрипта по пути через `~` (полным путём проходит);
  - иногда — без объяснений то, что раньше проходило (правка роутера по SSH 28.09.2026, чтение
    чата после дня успешных чтений). Отказ относится к цели, а не к форме команды: не
    переформулировать и не дробить.
- **Работает**: скрипт сам читает токен и не печатает его — блокируется вывод секрета в диалог, а
  не его использование; точечное правило на конкретный скрипт или действие (вписывает владелец);
  смена `defaultMode` с auto на обычный — вместо блока будет запрос подтверждения.
- **Классификатор — внешняя модель и бывает недоступен** («… is temporarily unavailable … auto
  mode cannot determine the safety of Bash», 03.09.2026): отваливается весь Bash, включая `cat`,
  а Read/Edit/Write работают — правки делать ими, не ждать.
- **«Classifier gave no verdict (it skipped this action)»** — другой отказ: жёсткий, повтор даёт
  то же, причину не называет. 04.10.2026 так отказывали все Edit в `mods/msk-time` (мод загружен в
  ту же сессию — гипотеза, не проверено). Обход — владелец переключает режим сессии на ручной,
  правки идут с подтверждением; через Bash те же правки не делать.
- **Свои правила `autoMode`**: `claude auto-mode defaults` / `config` / `critique` — стандартные
  правила, действующие и разбор своих формулировок. Свой `autoMode.allow` **заменяет** стандартный
  список целиком — вписывать `defaults.allow` плюс свои. В `autoMode.environment` — доверенные
  домены и исключения. Правило подхватывает только новая (перезапущенная) сессия.
- Согласие через вывод инструмента (ответ бота «да») правилом не сделать: для классификатора это
  данные, их можно подделать; пересказ агентом тоже не считается.
- Записать себе в память правило, ослабляющее ограничение, агенту не дадут [Instruction
  Poisoning] — такое правило вписывает владелец сам.

## Правила

- **Блок классификатора — не обходить.** Разовое действие — остановиться, описать владельцу,
  что и зачем, ждать явного «запускай». Действие, которое владелец хочет от меня регулярно, —
  сразу:
  1. узкое правило для `autoMode.allow` (что разрешено, при каком условии, что остаётся
     запрещено) — в файл;
  2. владельцу одна команда: на Mac и Linux `~/.claude/bin/automode-add-rule <файл>`, на Windows
     `python <kit>/bin/automode-add-rule <файл>` (`python3` там часто нет). Скрипт делает бэкап
     `settings.json`, не плодит дублей, проверяет JSON; своего `autoMode.allow` ещё нет — сначала
     вписывает стандартные из `claude auto-mode defaults`, без них ничего не пишет;
  3. предупредить: правило подхватит только перезапущенная сессия.

  Одно правило — на один вид действия: «выдать всё разом» нельзя, широкое правило классификатор
  сам не примет. *Почему:* владелец (30.09.2026): «задолбался постоянно обходить
  классификатор… если это сведётся до одной команды — хорошо».
- Готовый скрипт, на который пришёл отказ, сохранить в постоянное место, не только во временную
  папку.
