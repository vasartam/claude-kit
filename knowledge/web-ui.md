# Веб-интерфейсы: вёрстка, проверка, конкурс дизайнов

- **Скриншоты без установки браузера** — безголовый Chromium, который уже стоит: в Windows
  `msedge.exe`, в macOS `"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome"` (или
  Microsoft Edge там же), в Linux `chromium`. Флаги одни: `--headless=new --disable-gpu
  --hide-scrollbars --allow-file-access-from-files --virtual-time-budget=4000
  --window-size=1440,2600 --screenshot=<png> <url>`; PNG агент смотрит через Read. Chrome в macOS после
  снимка может не выйти сам (22.10.2026, `--headless=new`, Chrome 151: PNG за 2 с, процесс жив, Bash до таймаута):
  запускать в фоне со своим `--user-data-dir`, ждать, пока PNG перестанет расти, и закрывать процесс.
  Снимок — страница как есть, **без подсветки** (рамки, фон, стрелки дорисовывают то, чего на странице нет;
  владелец попросил убрать и переснять, 23.10.2026): место изменения — кадром и словами. Прокрутить к элементу —
  скачать HTML, вставить `<base href>` и `scrollIntoView`, снимать file://; окружение уже сняли — тот же HTML с
  `<base>` на рабочий хост (стили с теми же хешами там обычно есть). Окно уже
  ~500 px не бывает — **ширину телефона даёт страница-обёртка с `<iframe width=390>`**
  (медиазапросы считают ширину iframe). Тема — параметром `?theme=light|dark` в самой странице.
  Данные для file://-предпросмотра — `<script src="sample.js">` с `window.SAMPLE = {…}` (fetch на
  file:// не работает). Пример — `.design/shoot.sh` и `shoot-prod.sh` в проекте с прототипами.
- **CSP без `unsafe-inline`:** ни `<script>`/`<style>` в HTML, ни `style=""` (в том числе в строках
  JS) — размеры через `el.style.setProperty` или атрибуты SVG; каждая строка из API — через
  `esc()` и в тексте, и в атрибутах. Проверять подстановкой `<img onerror>` / `"><svg onload>`
  во все строковые поля и снимком DOM (`--dump-dom`).
- **Конкурс дизайнов работает** (личный проект, 26.09.2026): 3–4 агента с разными подходами делают
  живые прототипы на реальных данных и сами правят их по своим скриншотам → 3 судьи с разными
  взглядами (дизайнер, пользователь, фронтенд/доступность) → итоговая спецификация «база +
  прививки» → сборка → проверки (вид, правильность цифр, код/XSS) → исправления. Дорого
  (≈2,7 млн токенов у агентов) — только по просьбе владельца о «красивом интерфейсе».
- Прогнать хотя бы раз **в настоящем браузере** (браузер агента — `claude-in-chrome.md`: одна
  группа вкладок, надёжный ввод, фильтры секретов, прямые ссылки): тесты с ручными заголовками
  пропускают то, что делает браузер сам (`Origin: null`).
- UI-фичу не показывать человеку до самопроверки — навык `/screen-selfcheck` (матрица состояний,
  снимки, цикл «падающий тест → фикс»).
- **Сообщения об операциях — над длинной таблицей**, не под ней: отчёт об импорте, ошибку
  сохранения, предупреждения под сотней строк не увидят. Сдвиг таблицы при появлении баннера —
  меньшее зло: человек видит, что баннер появился; промах курсора из-за сдвига — проблема
  браузерной автоматизации, а не человека, и лечить её перестановкой интерфейса нельзя. Нашёл
  при самопроверке «баннер сдвигает контент» — не повод молча менять раскладку: перестановка
  блоков — изменение UX, его согласовывают с владельцем, а не проводят попутно.
