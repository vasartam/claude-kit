# Модели Claude: лимиты тарифа, стоимость, кэш

## Лимиты тарифа (Max)

- Окна на карточке: «5-hour», «Weekly · all models», «Weekly · Fable». **Пул один**: «Weekly ·
  Fable» — потолок внутри общего недельного (не больше 50 % на Fable), а не отдельный запас.
  Сообщение на Fable списывается в оба счётчика и «расходует лимиты быстрее других моделей»
  (множитель не публикуется): ради экономии недельного лимита на Fable не переключаться —
  экономить Sonnet на простых задачах. На Pro Fable в лимиты не входит — только за usage credits.
  Источник — support.claude.com, «Claude Fable models on your plan» (26.09.2026).
- `get_usage` из десктопа может назвать тариф «Pro», когда карточка показывает «Max (5x)»;
  проценты и время сброса при этом верные — верить им, не названию.
- Большие файлы, которые читает каждый агент (`AGENTS.md`, навыки, статус), быстрее сжигают
  пятичасовой лимит — держать их короткими, подробности по ссылке.

## Выбор модели и effort (Opus 5.5 / Fable 5.1)

- Цена API за токен: Fable 5.1 — 10/50 долл. за 1M (вход/выход), Opus 5.5 — 4/20, то есть
  Fable в 2,5 раза дороже. Источник — навык `claude-api` (26.09.2026).
- Уровни effort **не сравнимы между моделями**. По тестам Anthropic Opus 5.5 на `medium` не хуже
  Opus 5 на `high` в коде при вдвое меньшем расходе токенов, хотя на том же уровне думает дольше;
  у Fable 5.1 даже `low`/`medium` часто сильнее `xhigh` прошлых моделей. Сравнения «Fable medium
  против Opus 5.5 high» нет — оценку за замер не выдавать.
- Fable окупается выше обычного уровня (долгая самостоятельная работа, сложная отладка, система
  «с первого раза» по хорошему ТЗ, плотные картинки); на рутине выигрыша нет, лимит уходит быстрее.

## Какую модель и effort под задачу

Таблица — отправная точка, а не замер: сдвигать по опыту. По силе и цене: Haiku 4.5 → Sonnet 5.5 →
Opus 5.5 → Fable 5.1; effort: low → medium → high → xhigh → max.

| Задача | Модель / effort |
|---|---|
| механика: переименовать, найти по известному месту, прогнать команду, пересказать | Haiku 4.5 или Sonnet 5.5 / low–medium |
| рутина: мелкая фича, тексты, документация, память, хуки, настройки | Sonnet 5.5 / medium–high |
| обычная работа с кодом, отладка средней сложности, разбор с выводом | Opus 5.5 / medium–high |
| исследование, архитектура, большой рефакторинг, трудная отладка | Opus 5.5 / xhigh–max |
| долгая самостоятельная работа, система «с первого раза», плотные картинки | Fable 5.1 (лимит уходит быстрее) |

- На исходе лимита — на ступень дешевле: пятичасовой от 70 %, недельный — по дневной норме, а не
  по проценту недели (`model-advice.md`, «Лимиты»).

## Стоимость и кэш

- Минимальный кэшируемый префикс промпта у дешёвых моделей больше: Opus — 512 токенов,
  Sonnet — 1024, Haiku — 4096 (промпт на 2000 токенов на Haiku не кэшируется).
- Кэш **истории** диалога экономит больше кэша системного префикса (замер на агентном цикле:
  без кэша 5,96 долл., кэш истории 3,30, оба 2,37). Sonnet с кэшем оказался дороже Haiku без
  кэша (6,88 против 5,96).
- Сжимать текст ради токенов обычно вредно: придуманное сокращение распадается на больше
  токенов, чем целое слово.
- `claude-agent-sdk` в подпроцессе не может взять учётные данные Claude Code (короткоживущий
  токен); для headless нужен `CLAUDE_CODE_OAUTH_TOKEN` от `claude setup-token`.
  `ResultMessage.model_usage` отдаёт `cacheReadInputTokens` — кэш проверять фактом.
