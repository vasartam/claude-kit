# Claude Code: плагины

Проверено 04–29.09.2026 (CLI 2.1.28x) на своём плагине из локального маркетплейса; то же — в
сессии приложения. Набор подключается не плагином, а `scripts/link.py` (личные навыки и записи
в `settings.json`); станет публичным — перейти на плагин: слои уже разложены в его формате.

## Устройство

- **Namespace неотключаем**: навык плагина вызывается как `/<плагин>:<имя>`. Свой префикс в имя
  каталога не добавлять — выйдет `/<плагин>:<плагин>-<имя>`. Имя каталога, поле `name` в
  `SKILL.md` и имя вызова внутри namespace — одно голое имя.
- **Ссылка рядом с плагином задваивает навык**: тот же каталог и в `~/.claude/skills/<имя>`, и в
  плагине — два навыка, `<имя>` и `<плагин>:<имя>`. Выбирать одно.
- **Ставится из CLI без интерактива** (годится для установщика и headless):
  ```
  claude plugin marketplace add <каталог с .claude-plugin/marketplace.json>
  claude plugin install <плагин>@<маркетплейс> -y --scope user
  ```
  Обе пишут в `~/.claude/settings.json` (`extraKnownMarketplaces` с `source: directory` и
  абсолютным `path`; `enabledPlugins`) — руками не править. Проверка: `claude plugin list`,
  `claude plugin marketplace list`, `claude plugin details <плагин>` (инвентарь компонентов и
  оценка токенов).
- **Хуки плагин берёт только из `hooks/hooks.json`** (`${CLAUDE_PLUGIN_ROOT}` — каталог плагина).
  Голый `hooks/*.sh` не подхватывается: `details` покажет `Hooks (0)`.

## Кэш установки

- **Сессия грузит навыки и команды из кэша, а не из каталога маркетплейса**: `install` копирует
  плагин в `~/.claude/plugins/cache/<маркетплейс>/<плагин>/<version>/` (`installPath` и
  `gitCommitSha` — в `~/.claude/plugins/installed_plugins.json`). Правки репозитория туда сами не
  попадают: 25.09.2026 кэш оказался копией трёхнедельной давности без новых навыков и хуков.
- `claude plugin details` читает каталог, а не кэш — свежесть по нему не проверить; сверять
  `diff -rq <installPath> <репозиторий>/plugins/<плагин>`.
- **Освежить кэш**: поднять `version` в `.claude-plugin/plugin.json` →
  `claude plugin marketplace update <маркетплейс>` → `claude plugin update <плагин>@<маркетплейс>`;
  появится новый каталог `cache/…/<новая version>/`. При той же `version` update отвечает
  «already at the latest version» и кэш не трогает (26.09.2026).
- **`/reload-plugins` подхватывает новый кэш в открытой сессии** — перезапуск не нужен, надпись
  «Restart to apply changes» после `plugin update` вводит в заблуждение (29.09.2026: до reload
  навык загрузился старым, после — новым; ответ «Reloaded: N plugins · N skills · N hooks …»).
  Новый каталог навыка без reload не появляется.
- **Хуки плагина из каталожного маркетплейса выполняются прямо из репозитория**:
  `${CLAUDE_PLUGIN_ROOT}` у них указывает на каталог маркетплейса, не на кэш, — правка скрипта
  хука действует сразу (29.09.2026). Но новый хук или правку `hooks.json` идущая сессия видит
  только после `/reload-plugins`; уже случившееся событие задним числом не обработается.
- HTML-комментарии из тела `SKILL.md` в загруженный текст не попадают (та же проверка).

## Правила

- **Навык и команда для одного дела различаются именем, а не возможностями**: команда — с
  суффиксом `-cmd`, навык — без (`deploy-check` и `deploy-check-cmd`). Обе полнофункциональны, в
  описании каждой — что вторая делает то же самое. Переименовывая — каталог навыка, файл команды
  и все ссылки в документации. *Почему:* развести их по смыслу («навык объясняет, команда
  запускает») владелец отклонял трижды: навык, который не умеет запустить, бесполезен, а по
  суффиксу вида `-docs`/`-run` не понять, где навык, а где команда.
