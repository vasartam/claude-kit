# Письмо людям: документы

Документы, которые читают другие люди без контекста переписки: README, `docs/`, описание MR и
задачи, страница для коллег или заказчика, заметка со встречи. Внутренняя документация проекта
для агентов (`AGENTS.md`, журнал решений, статус) — навык `dev-method`; сообщения — `writing.md`.

## Факты — по первоисточнику

- К каждому утверждению — вопрос «откуда я это знаю». Переписка, скриншот, память, своя прошлая
  заметка — гипотеза о том, как было; идти в код, конфиг, задачу, воспроизводить.
- Конфиги и настройки внешних систем перечитывать **в день публикации** и писать дату проверки:
  они меняются без предупреждения.
- Где можно — воспроизвести и вставить фактический вывод, а не пересказ. Механику, выведенную из
  кода, подавать как вывод из кода (со ссылкой), а не как наблюдение.
- Своё предложение не выдавать за требование задачи — открыть задачу и проверить.
- В конце документа — раздел «что проверено» из трёх списков: проверено (и как), взято из
  переписки, не выяснено. Там же ограничения источников (старая локальная копия, недоступный
  сервис).

*Почему:* проверка первой версии документа нашла две ошибки: пример устарел за сутки (конфиг
переписали через час после чтения), механика из кода подана как наблюдение (2026-09-14).

## Решение, а не пересказ мотивов

В тексте для других людей — решение одной строкой: «что делаем / чего не делаем». Чужие мотивы
своими словами не пересказывать: это интерпретация, и она бывает неточной. Причину писать, только
если она проверяема (код, настройка, замер). Свою формулировку из чата в документ не копировать.
С `dev-method` («решение — с причиной и отвергнутыми вариантами») не спорит: там внутренний
журнал решений проекта, здесь — текст для людей без контекста.

*Почему:* «упоминание мобильной версии — не требование, а наследие старых правок» владелец
заменил на «для мобильной версии пока не делаем»: решение — факт, интерпретация — нет (2026-08-19).

## Прогноз — не факт

Фраза в будущем времени или с оговоркой («скорее всего», «может случиться», «думаю, будет»)
переносится в заметку как **прогноз названного человека**: «X ожидает, что …; сейчас — …», а не
как состояние мира. При переносе устного обсуждения сверять время глагола и модальность в
расшифровке. Сомнительное о внешнем мире — пометить автором и статусом, проверить или не писать.

*Почему:* заметки читают без расшифровки — ложный факт потом повторяется в отчётах; владелец
поймал подмену чужого прогноза фактом сразу (2026-09-25).

## Правка — в формате файла-хозяина

- Перед вставкой в существующий документ прочитать его (30–50 строк вокруг места, долю таблиц и
  списков) и вписать новое тем же способом: таблица — строкой, буллеты — буллетом; раздел `##`
  с абзацами — только где такие уже есть.
- Место — по смыслу: факт про создание сервиса не кладут в раздел про сборку. Не ложится ни в
  одну секцию — искать другой файл, а не заводить раздел. Узкий факт (команда, флаг) — строка;
  крупный самостоятельный сюжет — отдельный файл и строка в индексе.
- После серии вставок перечитать свои правки глазами ревьюера: похоже на остальной файл?

*Почему:* «в файле очень кратко… а мы тут большую пелёнку текста, не структурированную никак» —
инородный по формату кусок обесценивает файл, даже если факт верный (2026-08-14).

## Без локальных путей

В документе для других людей не ссылаться на свои локальные пути: домашний каталог, память
агента, личные заметки, `~/.claude/…`. Для читателя это тупик — файла у него нет. Нужен факт —
перенести сам факт; нужен только себе — не упоминать. Исключение: содержимое на следующих шагах
уезжает в общее место, и в тексте сказано куда. Перед публикацией — `grep -nE '/Users/|/home/|~/'`
по файлу и `D:\`, `C:\` для Windows.

## README, docs/, CHANGELOG

Раскладка для инструмента, который другие ставят себе:

| Файл | Что там |
|---|---|
| `README.md` | описание и установка — и больше ничего; установка — командами и тем, что спросит установщик, а не рассказом |
| `docs/*.md` | как работает сейчас, без «раньше было так» |
| `CHANGELOG.md` | что менялось, новое сверху |

Читатель README ставит инструмент и ничего о нём не знает: что не нужно для установки — в
`docs/`. История — только в `CHANGELOG.md`, из README и `docs/` на неё не ссылаться. В проектах
по `dev-method` — его схема (журнал решений, где устаревшее зачёркивают); «без истории» там —
про описание устройства.

*Почему:* «историю не будем писать в readme… лучше нигде на историю не ссылаться», «слишком
здоровый readme» — 621 строка ушла в `docs/`, осталось 163 (2026-09-01).
