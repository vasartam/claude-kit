# Claude Code: навыки, файлы инструкций, память

Что сессия грузит сама, кроме разговора. Обзор тем — `claude-code.md`.

## Навыки

- **Личные навыки** — `~/.claude/skills/<имя>/SKILL.md` (набор кладёт туда ссылки,
  `scripts/link.py`), видны во всех проектах и worktree, не в облачных сессиях. Личный навык
  важнее проектного с тем же именем. Папка навыка может быть ссылкой (symlink, на Windows
  junction) — Claude читает цель. Правки `SKILL.md` подхватываются в идущей сессии без
  перезапуска. Навык из плагина грузится иначе — `claude-code-plugins.md`. Свой навык напрямую
  в `~/.claude/skills` не класть — в репозиторий (`tooling-repos.md`).
- Навык во вложенном `.claude/skills/` виден при работе в этом каталоге.
- **Список навыков в каждом ходе ограничен бюджетом** (бинарь 2.1.291): окно в токенах × 4 ×
  `skillListingBudgetFraction` (settings.json, по умолчанию 0.01 — 1 % окна) символов; переменная
  `SLASH_COMMAND_TOOL_CHAR_BUDGET` задаёт бюджет напрямую. Не влезает — описания укорачиваются,
  часть навыков остаётся **с одним именем**, и по смыслу такой навык уже не вызывается. Потолок
  одного описания — `skillListingMaxDescChars` (1536). *Почему важно:* при ~100 навыках (06.10.2026)
  около 30 шли без описания, в том числе навык, куда перенесли правила, — правила терялись сильнее,
  чем в памяти. Прежде чем добавлять навыки — убрать двойники и сократить длинные описания;
  поднять долю — ценой контекста в каждом ходе.
- **Спрятать навык, не удаляя файлов** — `skillOverrides` в `~/.claude/settings.json`:
  `{"<имя>": "off" | "user-invocable-only" | "name-only" | "on"}` (`off` — не видят ни модель, ни
  `/имя`; `user-invocable-only` — только по `/имя`; `name-only` — в списке без описания); то же —
  окно `/skills`. Работает, даже когда сторонний установщик снова кладёт навык в `~/.claude/skills`.
  **На навыки плагинов не действует:** ключ `<плагин>:<навык>` со значением `off` навык из списка не убрал
  (07.10.2026, 2.1.292; навыки claude.ai с префиксом `anthropic-skills:` и голые имена из `~/.claude/skills`
  выключились). Навык плагина убирают из самого плагина или весь плагин — `claude plugin disable`.
  Править `settings.json` самой сессии в режиме auto не даёт классификатор (Self-Modification) —
  делает владелец. Плагин целиком выключает `claude plugin disable <плагин>@<маркетплейс>` — эту
  команду классификатор пропустил (06.10.2026); включить — `claude plugin enable …`.

## CLAUDE.md и AGENTS.md

- **`~/.claude/CLAUDE.md`** грузится в каждую сессию; импорты в нём (строка `@<путь>`,
  относительно файла или абсолютный, до 4 уровней) — без окна подтверждения, кроме сессий
  Cowork. Импорт внешнего файла из **проектного** `CLAUDE.md` спрашивает подтверждение один раз
  на проект; дотянуться им до соседнего репозитория нельзя.
- **Claude Code читает `CLAUDE.md`, а не `AGENTS.md`** (бинарь 2.1.235–2.1.237 и документация
  memory); ещё — `CLAUDE.local.md`, `.claude/rules/`. Codex и OpenCode читают `AGENTS.md`, Cursor —
  `.cursor/rules`, Copilot — `.github/copilot-instructions.md`. Репозиторий под разные агенты:
  содержательный `AGENTS.md` и `CLAUDE.md` из одной строки `@AGENTS.md` (так устроен и набор).
  Симлинк `CLAUDE.md → AGENTS.md` на Windows требует прав администратора.
- Вложенные `CLAUDE.md` грузятся **по требованию** — когда агент читает файлы из их каталога;
  после `/compact` возвращается только корневой.

Поддержка меняется от версии к версии — проверять по бинарю или документации, а не по памяти.

## Память

- Память Claude Code (`~/.claude/projects/<папка>/memory/`) привязана к папке сессии: сессия в
  другой папке или в worktree её не видит. Поэтому общее — в наборе, проектное — в репозитории
  (`session-hygiene.md`).
- Большая память — деревом разделов с индексами `MEMORY.md` (сканер: рекурсия, лимит 200 файлов,
  обрезка корневого индекса ~24,4 КБ) — `skills/session-extract-knowledge/references/memory-layout.md`.
