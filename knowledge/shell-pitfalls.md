# Грабли оболочек: кавычки, контейнеры, деплой, секреты

Общее для любой ОС. Windows (инструмент Bash на Windows, Git Bash, PowerShell, WSL) —
`windows/knowledge/shell-pitfalls.md`.

- **Вложенные кавычки** (`ssh host "… \"…\" …"` внутри ещё одного слоя оболочки) ломаются
  постоянно. Надёжно: скрипт в файл (scratchpad) и через stdin — `ssh host 'sh -s' < script.sh`.
- **Отладка в контейнере** — `docker compose run --rm` (отдельный контейнер), а не `exec` в
  работающий: при нехватке памяти ядро убьёт сам сервис.
- **Самообновляемый скрипт деплоя** (`git reset` внутри) — правка действует со следующего
  деплоя: текущий процесс дочитывает старую версию.
- **Секреты в выводе.** Не печатать даже в своих командах: пути файлов локального
  `telegram-bot-api` содержат токен бота; ключи маскировать (`sed`), проверять только длину и
  формат. Значения переменных CI не выводить — только имена и типы.
- **zsh `print` со строкой, начинающейся с `-`** (`print "--- итог"`) — `bad option: -`, при `set -e`
  скрипт обрывается на этой строке (03.10.2026). Писать `print -- "…"` или `printf '%s\n' "…"`.
- **zsh не делит переменную на слова**: `CMD="python3 x.py token"; $(…$CMD…)` ищет программу с
  именем всей строки — `no such file or directory`, подстановка пустая, запрос ушёл без токена (401),
  цикл прошёл по всем элементам (05.10.2026). Команду — функцией или прямо на месте, не в строке.
- **zsh: слово с `=` в начале** (`echo ====` как разделитель) — equals expansion ищет команду `===`, `not found`,
  цепочка обрывается (25.09, 14.10 и дважды 23.10.2026). Разделитель — `echo ---` или в кавычках, никогда `=`.
- **`grep` — это `ugrep`** (если так в оболочке): `-oE '.{0,200}слово.{0,200}'` по UTF-8 падает «exceeds complexity
  limits» (14.10.2026). Контекст вокруг совпадения — `python3 -I` с `re`, либо квантификатор поменьше. По файлу в
  однобайтовой кодировке (HTML в windows-1251) молча не выводит ничего, даже `-c` (23.10.2026: Python с
  `encoding='cp1251'` нашёл 148 совпадений там, где `grep -c` промолчал) — пустой вывод не значит «нет совпадений»,
  такой файл читать Python с явной кодировкой.
- **`--help` чужого скрипта — не проверка.** Самописный скрипт без разбора ключей на `--help` делает своё главное
  действие. Прежде чем запускать скрипт с побочным эффектом (сборка, запись, отправка), прочитать его `main`; проверять
  — `python3 -c 'import ast; ast.parse(…)'` или ключом, который он точно разбирает (2026-10-12: `--help` поставил в
  очередь сборку, создающую MR; успел отменить). В своих скриптах неизвестный ключ — справка и выход.
- **`pipefail` и `cmd | grep -q` как проверка.** Цепочка падает, если упала любая команда, даже когда `grep`
  нашёл строку: `ssh -T git@github.com` выходит с 1 и при успешном входе («does not provide shell access») — проверка
  ключа под `set -o pipefail` ложно отказывала (13.10.2026). Вывод — в переменную (`out=$(cmd 2>&1 || true)`), потом
  сравнение `[[ $out == *"…"* ]]`.
- **`curl` и `[]{}` в адресе** — это его глоббинг: запрос с регуляркой в параметре
  (`filter=original:.*/reel/[A-Za-z0-9_-]{9,}`) тихо вернул пустой ответ (15.10.2026). Ключ `-g`
  (`--globoff`) или собрать адрес в Python (`urllib.parse.urlencode`).
- **`pkill -f <образец>` убивает свою же оболочку**: в `bash -c '…; pkill -f collect_links.py; …'`
  образец есть и в командной строке самой `bash`, она получает SIGTERM — вся команда «Exit code 15»,
  остальное не выполнилось (15.10.2026). Образец, который не совпадёт сам с собой: `pkill -f
  '[c]ollect_links.py'`, или `pgrep -f` → проверить список → `kill PID`.
- **`awk` и русская локаль (macOS, BWK awk).** При `LC_NUMERIC=ru_RU` он читает `224.185` как `224` и печатает дробные
  с запятой: суммы и длительности молча округляются (`echo '224.185 1.5' | awk '{print $1+$2}'` → `225`, 22.10.2026).
  Для расчётов — `LC_ALL=C awk …`. GNU awk по умолчанию локаль для ввода не берёт.
