# CHANGELOG

## 2026-10-14 — context-guard на Node

- Хук context-guard теперь `hooks/context-guard.mjs` (Node 18+, без зависимостей), его источник
  состояния — `hooks/session-state.mjs`; поведение и файлы — как у Python-версий, тесты сверяют одно с
  другим (`hooks/README.md`). Зачем: часть каталогов плагинов принимает хуки только на Node.
- `scripts/link.py`: первое слово `node` в `hooks.json` → node из PATH (абсолютный путь), 18+. Нет такого —
  переходно подключается Python-версия того же хука рядом (`context-guard.py`), нет и её — хук пропущен.
  Переход на машине: `git pull`, `link.py`; Node нет — поставить, иначе хук останется на Python.
- `context-guard.py` и заглушки по старым путям (`knowledge_guard.py`, `terminal/hooks/context-guard.py`)
  удалить следующим выпуском. `session_state.py` остаётся: на нём model-advisor и limit-guard.

## 2026-10-13 — уборщик групп вкладок «Claude»

- Новый каталог `chrome/` — расширения Chrome, ставятся вручную («Загрузить распакованное»).
  `chrome/claude-groups-cleaner` закрывает брошенные группы вкладок «Claude» (README там же).

## 2026-10-12 — набор публичный: личное — в личный слой, часы — настройкой

- Набор публичный: github.com/vasartam/claude-kit, одним слепком без истории; прежний gitlab.com
  репозиторий — в архив. Своя копия: `git remote set-url origin git@github.com:vasartam/claude-kit.git`,
  `git fetch`, `git reset --hard origin/main` (незапушенное — сначала в патч). Имя владельца, аккаунты, почта коммитов, словарь его имён для голоса, личные
  проекты и образец «утренней газеты» ушли в приватный личный слой (`claude-kit-personal`), в наборе —
  нейтрально («владелец», «личный проект»).
- Часы — ключ `clock` в `~/.claude/claude-kit.json`: `utc_offset`, `label`, `farewell` (`hooks/README.md`,
  msk_time). Без ключа — пояс системы, подпись «UTC+N», прощания нет (сессия кончается «Готово.»). Своё
  владелец задаёт на каждой машине; `link.py --init` прочие ключи конфига теперь сохраняет.
- Личный слой разделён: корень — на всех машинах владельца, `home/` — только домашняя. Переход на машине —
  `origin` набора на GitHub, `link.py --init <слои>,<личный>[,<личный>/home]`, ключ `clock`.

## 2026-10-07 — model-advisor: совет и `wait:` решает код

- Совет сменить модель/effort/ultracode и `wait:` (ожидание `claude-autocontinue`) хук выдаёт сам по
  таблице (`hooks/README.md`, «model-advisor»): только при `limits tight` и дорогих настройках, один раз
  на окно лимита (`session-status/<sid>.advice.json`). Раньше `wait:` шёл к каждому промпту под herdr, а
  решала модель по тексту правил — ждала 2 мин, когда менять нечего, и повторяла совет (поправки
  владельца 07.10.2026). Правила слоя terminal свелись к «есть `wait:` — совет и ожидание, нет — работать».

## 2026-10-04 — время лимитов и размер контекста после сжатия

- context-guard и model-advisor на первом промпте после сжатия брали последний ответ до сжатия: граница
  ещё не была дописана в транскрипт (319k при 28k). Теперь context-guard на `SessionStart` после сжатия
  пишет отметку `<id>.compact.json`, и `session_state` показания старше неё не берёт.
- `terminal/bin/claude-statusline`: `ts` в `rate-limits.json` обновляется на каждом новом ответе API сессии, а
  не только при смене процентов. Раньше model-advisor писал «лимиты — данные 73 мин назад» при живой строке.

## 2026-10-04 — сжатие без панели herdr — модом

- Мод `mods/context-compact`: без панели herdr (приложение, терминал вне herdr) context-guard после
  раскладки просит модель выполнить `echo context-compact [--resend <файл>] -- <инструкция>`; мод после хода
  запускает `/compact` (`$.command.run`) и присылает запрос заново — как `claude-compact`. Без мода —
  прежняя просьба владельцу. Причина — владелец не хочет набирать `/compact` сам (04.10.2026).
- Проверено дома (приложение, Windows, сессия ~371k, 04.10.2026 02:34): сжатие и продолжение пришли без
  владельца. Сигнал теперь — в двойных кавычках (`echo "context-compact … -- <инструкция>"`): без них `;`
  в инструкции резал команду оболочки, и модель повторяла сигнал.

## 2026-10-04 — время ответа ставит мод

- Мод `mods/msk-time`: дописывает `_ДД.ММ.ГГГГ ЧЧ:ММ МСК_` в конец ответа хода прямо в потоке
  (`turn.step`), в терминале и в приложении. Модель метку больше не пишет; `hooks/msk_time.py` по признаку мода не требует её в Stop и
  говорит «не пиши». Без мода (`exclude: ["msk-time"]`, сессия до подключения) — прежняя схема.
  Причина — модель досчитывала время на глаз и писала будущее (решение владельца 04.10.2026).

## 2026-10-03 — состояние сессии, хуки контроля в общем слое

- Хуки контроля — в общем слое, в любой оболочке: `terminal/hooks/context-guard.py`, `model-advisor.py`,
  `limit-guard.py` → `hooks/`; `hooks/knowledge_guard.py` слит с context-guard в `hooks/context-guard.py`.
  Имена для `exclude` прежние (`context-guard`, `model-advisor`, `limit-guard`); `knowledge_guard`
  больше ничему не соответствует — `link.py` предупреждает о мёртвой записи. В `terminal/hooks/` —
  только `api-error-autocontinue`. Подробно — `hooks/README.md`.
- context-guard — одна схема на обеих машинах (решение владельца 2026-10-03): с 300k вопрос на старте
  промпта, отсрочка цитатой «> контекст Nk, проверка отложена до Mk», с предела — требование. От
  оболочки зависит только концовка: в панели herdr — `claude-compact --resend`, как было; без неё —
  раскладка, запрос и просьба владельцу набрать `/compact`, ручное `/compact` без раскладки
  откладывается один раз, автосжатие ждёт отметки. Лестница 50/75/90 % и напоминания на `Stop` ушли,
  `knowledge-guard:` в текстах → `context-guard:`, `echo knowledge-keep-context` — переходная отсрочка.
  Пороги — от порога автосжатия (`HARD_eff`, `BASE_eff`), отказов автосжатию — не больше 40,
  субагентов хук не трогает. Состояние — `~/.claude/context-guard/`, прежнее `knowledge-guard/`
  подхватывается без волны напоминаний. Исправлено: `<sid>.prompt.md` больше не удаляется до
  повторной отправки запроса `--resend`. Сессии Mac вне herdr получают концовку без панели.
- Мод `mods/session-state` и модуль `hooks/session_state.py`: модель, effort, ultracode, контекст,
  порог автосжатия, лимиты и дневная норма — из самого свежего источника (мод, статусная строка,
  транскрипт), в том числе в приложении. Токены контекста — без вывода. Лимиты годны, пока их сброс
  впереди (вместо «не старше 15 мин»).
- model-advisor: контекст относительно автосжатия, возраст лимитов, «?» вместо «не поддерживается»,
  при `limits tight` — действие; правило совета — `knowledge/model-advice.md`. Без панели herdr — без
  `wait:` и метки вкладки.
- limit-guard молчит, пока жив координатор: файлы `~/.claude/limit-guard/alive-limit-guard` (30 мин) и
  `alive-night-work` (75 мин) пишут навыки `limit-guard` и `night-work`. Без координатора работает сам
  и дома (решение владельца). `LIMIT_GUARD_FILE` убран, тесты — через `CLAUDE_CONFIG_DIR`.
- `link.py` ведёт моды: `<слой>/mods/<имя>/` → `env.CLAUDE_CODE_PLUGIN_DIRS` (свои записи, в том числе
  ручные с `~`, заменяет, чужие не трогает); ручная запись мода `agent-view-status` больше не нужна.
- Заглушки по старым путям — `hooks/knowledge_guard.py`, `terminal/hooks/context-guard.py`,
  `model-advisor.py`, `limit-guard.py`: передают вход новому хуку и держат живые сессии со старым
  снимком хуков. **Удалить следующим выпуском, после перезапуска всех сессий на обеих машинах**.
- Переход на Mac (терминал, herdr):
  1. `python3 <kit>/scripts/link.py --check`, затем без `--check`: хуки общего слоя, в
     `CLAUDE_CODE_PLUGIN_DIRS` — `mods/session-state` и `terminal/mods/agent-view-status` (ручная
     запись заменится).
  2. Убрать `knowledge_guard` из `exclude` в `~/.claude/claude-kit.json`.
  3. Подхват хуков без перезапуска: в живой сессии — промпт; в `~/.claude/context-guard/<sid>.json`
     появилось поле `baseline` или пришла строка model-advisor «… до автосжатия» — подхватываются на
     лету, нет — сессия идёт через заглушки. Итог — в `knowledge/claude-code-hooks.md`,
     «Запись и подхват» (файл у предела 8 КБ — без роста).
  4. Перезапустить сессии (`/restart-session`): мод грузится при старте.
  5. Проверка: после промпта есть `~/.claude/session-status/<sid>.state.json` с `auto_compact_at`,
     строка model-advisor с «до автосжатия», `⚑` в статусной строке.
- Переход дома (Windows, приложение):
  1. `git pull` (WSL), затем тесты Windows-Python: `python hooks\test_<имя>.py` по каждому файлу и
     `python scripts\test_link.py`. Красное — остановиться, `link.py` не запускать.
  2. `python scripts/link.py`, полный перезапуск приложения; ручной путь мода-пробника пока не снимать.
  3. Разделитель `;`: после промпта есть и `<sid>.state.json`, и файл пробника — грузятся оба каталога.
     Только тогда владелец убирает ручной путь пробника из `CLAUDE_CODE_PLUGIN_DIRS` и снова
     перезапускает приложение.
  4. Проверка: к промпту приходит строка model-advisor без `wait:`, в текстах хука — `context-guard:`,
     состояние сессии перенеслось без волны напоминаний.
  5. Через неделю можно удалить `~/.claude/knowledge-guard/`.
- Без мода (сессия не перезапущена) хуки работают на прежних источниках: в терминале — статусная
  строка, в приложении — транскрипт.

## 2026-09-25 — набор заведён

- Навык `dev-method` переехал сюда из личного проекта; копии в других проектах удалены, их два своих
  правила — «тест зовёт ту же точку входа, что приложение; эталон, а не прошлый прогон» и «чужое
  незакоммиченное — отдельным коммитом» — влиты в `references/testing.md` и `references/agents.md`;
  в `AGENTS.md` проектов — указатель.
- В `knowledge/` — общие пункты из памяти Claude Code разных проектов и их документации, переписанные
  обобщённо.
- Почему отдельный репозиторий, а не плагин, submodule или копии: плагин ставится в кэш (правки
  затираются обновлением); submodule фиксирует коммит и не доезжает до worktree агентов; копии
  расходятся (одна отстала на переделку за сутки). Один репозиторий на навыки и знания — решение
  владельца: всё переиспользуемое в одном месте.
